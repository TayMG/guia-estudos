Se o básico já está sólido

A banca deste professor costuma ir além de “o que é container”. Vá para Banca difícil: lá estão as perguntas de mecanismo, número e contrafactual — por que o HPA subiu em degraus, o que muda sem hostPID, quem é o PID 1 do Nginx, o que acontece se o crond morrer e como responder quando ele sair do escopo.

O projeto em 30 segundos

Três daemons diferentes, cada um em sua imagem, todos orquestrados por Kubernetes, com uma API em Python que enxerga e controla os processos do sistema operacional.

Visão geral
Nginx + Cronnginx:alpine + busybox crond
serve a página e escreve cron.txt a cada minuto
Process Manager APIPython 3.11 + FastAPI + psutil
lista, inspeciona, inicia e encerra processos
Cron separadoalpine + busybox crond
agendador isolado, escreve em cron-task.log
↓ orquestrados por ↓
Deployment nginx2 réplicas
Deployment api2 réplicas + HPA 2→10
Deployment cron1 réplica
↓ expostos por ↓
nginx-serviceNodePort 30081
api-serviceNodePort 30080
namespace daemon-labtudo isolado aqui

O que o trabalho demonstra, em uma frase: containers isolam processos; o Kubernetes mantém o estado desejado (recriando o que cai e escalando o que enche); e a API prova que, ao compartilhar o namespace de PID do nó (hostPID: true), um processo dentro de um container pode observar e controlar os processos do sistema operacional.
