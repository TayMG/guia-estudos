Evidências: o que o repositório realmente prova

Uma apresentação forte não é a que tem mais slides; é a que consegue apontar a linha exata que sustenta cada afirmação. Esta página organiza as provas disponíveis — e as que não existem.

Sem screenshots inventados

O repositório não tem prints do painel, não tem deploy, não tem vídeo de demonstração. Este site não cria “evidências” falsas. As provas abaixo são código, testes, SQL e o PDF. Se a banca pedir uma demo visual, a resposta honesta é: “a UI não foi implementada; o núcleo e os testes estão prontos”.

2. A prova mais bonita: o traço dos testes

O teste test_regra_alexandre_com_dados_extrator monta 2 super, 3 padrão e 2 convencionais e espera exatamente:

#ChamadoNívelEtapa/contador depoisPor quê
1S0super0 / 080+ absoluto; contador intacto
2S1super0 / 0ainda há super
3P0padrão0 / 1primeira padrão
4P1padrão1 / 0segunda padrão; cota 2 atingida
5C0convencional0 / 0uma convencional; cota 1 atingida
6P2padrão0 / 1volta ao início do ciclo

O teste test_fifo_super_e_intercalacao_21 prova o mesmo com outros nomes: 2S, 3P, 2C → S1, S2, P1, P2, C1. E test_super_nao_altera_contador_do_ciclo_21 prova o caso mais sutil: P0, S0, P1, C0. Se você sabe reproduzir esses três, sabe o algoritmo.

Como usar isso na banca

Não leia o código inteiro. Abra o teste e diga: “a especificação executável está aqui; eu vou traçar o caso de seis chamadas”. Em 40 segundos você mostra mais domínio do que lendo 200 linhas.

4. Como gerar sua própria evidência

Você não precisa acreditar neste site: rode os comandos. A suíte está pronta e usa um extrator falso, então não depende de rede para os 14 primeiros testes.

python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
pip install pandas

python -m unittest testes_frente2.py -v
# saída esperada (nomes podem variar na ordem): test_anti_inanicao_sob_pico_de_padrao ... ok test_ciclo_encurta_quando_prioritarias_vazias ... ok test_fila_convencional_vazia_nao_quebra ... ok test_fifo_convencional ... ok test_fifo_super_e_intercalacao_21 ... ok test_prioridade_absoluta_80_mais_e_ciclo_21 ... ok test_regra_alexandre_com_dados_extrator ... ok test_super_nao_altera_contador_do_ciclo_21 ... ok test_extracao_real_supabase ... skipped (sem env) ... ---------------------------------------------------------------------- Ran 15 tests OK (skipped=1)

Esse bloco é uma saída esperada, não uma captura de tela. O número de testes é 15; o único que pode ser pulado é o de integração real. Se você rodar com .env válido, ele tenta conectar; sem rede ou sem credencial, ele é skip.

6. Roteiro de demonstração em 3 minutos

  1. Abra modelos.py e explique os três níveis e o frozen=True. 30 s.
  2. Abra Alexandre.py e mostre o if fila_super e o _limites=(2,1). 40 s.
  3. Abra o teste 2 (super no meio do ciclo) e trace P0, S0, P1, C0. 50 s.
  4. Abra o teste 8 (100P + 1C) e diga por que a convencional não morre de fome. 30 s.
  5. Abra o SQL e aponte o índice parcial e a RLS aberta. 30 s.
  6. Feche com a frase de limitações: “núcleo pronto; UI e transação pendentes”. 20 s.
A evidência que mais convence

Não é um print bonito: é você apontar a linha do teste e dizer o que ela prova. A banca vê que você entendeu o contrato, não só a tela.
