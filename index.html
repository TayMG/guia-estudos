1. Fundamentos do Computador

Antes de entender como a arquitetura Intel funciona, precisamos saber como um computador se comunica internamente. Existem 3 blocos fundamentais:

┌──────────────────────────────────────────────────────────────┐ │ BARRAMENTO (BUS) │ │ ┌───────────────┐ ┌───────────────┐ ┌───────────────┐ │ │ │ Endereço │ │ Dados │ │ Controle │ │ │ └───────────────┘ └───────────────┘ └───────────────┘ │ │ ▼ ▼ ▼ │ │ ┌───────────────┐ ┌───────────────┐ ┌───────────────┐ │ │ │ CPU │ │ MEMÓRIA │ │ E/S │ │ │ │ (UC / ULA) │ │ │ │ (In / Out) │ │ │ └───────────────┘ └───────────────┘ └───────────────┘ │ └──────────────────────────────────────────────────────────────┘

1.1 Barramento (Bus)

O que é: É o "caminho" por onde viajam as informações entre os componentes do computador. Pense nele como uma autovia com 3 faixas:

FaixaO que transportaPor que existe
EndereçoIndica ONDE na memória o dado está ou deve ser gravadoSem ela, o processador não saberia onde ler/escrever
DadosOs valores reais (números, instruções, etc.)É a "carga" que está sendo transportada
ControleSinais de comando (ler, escrever, clock)Coordena quem fala, quem ouve e quando

1.2 CPU (Unidade Central de Processamento)

O "cérebro" do computador. Suas principais partes:

ComponenteFunção
UC (Unidade de Controle)Busca, decodifica e coordena a execução das instruções. É o "maestro".
ULA (Unidade Lógica e Aritmética)Realiza cálculos (soma, subtração, AND, OR, etc.).
PPUProcessamento auxiliar (frequentemente associado a operações de ponto flutuante).
MMU (Memory Management Unit)Gerencia a tradução de endereços lógicos → físicos (segmentação e paginação).
RegistradoresMemórias ultrarrápidas internas da CPU. Guardam dados, endereços e estado da execução.
A CPU também se comunica pelo barramento: envia endereço e controle e recebe/envia dados.

1.3 Memória

TipoTecnologiaCaracterísticasPor que importa
Principal (RAM)DRAM (Dynamic RAM)Grande capacidade, mais barata, precisa de refresh constanteArmazena programas e dados em execução
CacheSRAM (Static RAM)Pequena capacidade, muito rápida, não precisa de refreshReduz a espera da CPU por dados da RAM

Níveis de Cache:

  • L1 — Dentro do core, mais rápida (cerca de 1-4 ns), menor capacidade (~32-64 KB)
  • L2 — Pode ser dentro ou fora do core, intermediária (~10 ns, 256 KB-1 MB)
  • L3 — Compartilhada entre cores, maior (~30 ns, 2-64 MB)
Quanto mais perto da CPU, mais rápida e mais cara é a memória. A cache "aproxima" os dados frequentes da CPU para não ficar esperando a RAM lenta.

1.4 Entrada/Saída (I/O)

São os dispositivos que permitem ao computador receber dados (input) e enviar dados (output) — teclado, mouse, monitor, disco rígido, rede, etc.

2. Arquitetura Intel x64

2.1 Conceitos Fundamentais

Tamanho da palavra: É a capacidade mínima de bits para representar a instrução mais simples do processador. Ela também define a quantidade mínima de bits que a unidade decodificadora processa a cada ciclo de decodificação.

Por que isso importa? Se o processador decodifica de 8 em 8 bits, então a palavra mínima é de 8 bits. Uma instrução como ADD END1, END2 é quebrada em pedaços de 8 bits para ser interpretada. Uma palavra maior permite instruções mais complexas e endereçamento maior, mas exige circuitos mais sofisticados.
Instrução: ADD END1, END2 → END1 ← END1 + END2 ┌─────────────┐ ┌─────────────┐ │ Opcode │ │ Operandos │ │ (operador) │ │ (endereços) │ └──────┬──────┘ └──────┬──────┘ │ │ ▼ ▼ Decodifica Decodifica de 8 em 8 de 8 em 8 Se a palavra = 8 bits, cada ciclo lê/decodifica 8 bits
Relação: + tamanho da palavra = + núcleos simultâneos de decodificação
Uma palavra maior permite que a CPU decodifique mais instruções ao mesmo tempo, aumentando o paralelismo interno.

Compatibilidade Binária

Dois processadores possuem compatibilidade binária se:

  • Possuem o mesmo conjunto de instruções (ISA — Instruction Set Architecture)
  • Possuem a mesma representação em bits para essas instruções
OBS: TODAS as instruções devem ser iguais. Se apenas uma for diferente, toda a compatibilidade binária se perde. Um programa compilado para um não roda no outro.

Capacidade de Endereçamento

É a capacidade máxima de endereços que um processador consegue gerar em um sistema de memória.

  • Na maioria dos sistemas, cada endereço armazena 1 byte (8 bits) de informação.
  • Se o processador usa N bits para formar um endereço, ele consegue endereçar 2N bytes.
Bits de endereçoEspaço endereçávelExemplo de uso
16 bits2¹⁶ = 64 KB8086
20 bits2²⁰ = 1 MB80286 (modo real)
32 bits2³² = 4 GB80386+
64 bits2⁶⁴ = 16 EBArquitetura x64 moderna

Clock (Frequência do Processador)

O clock é o "batimento cardíaco" do processador. É um sinal elétrico que pulsa em uma frequência fixa, e a cada pulso (ciclo) o processador executa uma operação básica.

ConceitoO que éExemplo
Frequência de clockQuantos milhões/bilhões de ciclos por segundo (MHz/GHz)3.5 GHz = 3.500.000.000 ciclos/segundo
Ciclo de clockTempo entre dois pulsos consecutivosEm 3.5 GHz: ~0.28 nanosegundos por ciclo
CPI (Cycles Per Instruction)Quantos ciclos uma instrução leva para executarUma instrução simples pode levar 1 ciclo; complexa, vários
Velocidade ≠ Clock sozinho. Dois processadores com o mesmo clock podem ter velocidades diferentes por causa da arquitetura interna (pipeline, cache, número de núcleos). Mas, tudo o mais constante, maior clock = mais operações por segundo.
Relação com o tamanho da palavra: Um processador com palavra de 64 bits processa mais dados por ciclo que um de 32 bits, mesmo no mesmo clock. A velocidade real depende de: Velocidade = Clock × Bits da palavra / CPI

Hardware define o limite máximo de velocidade. Software define o quão eficientemente esse limite é aproveitado.

3. Modo Protegido

O modo protegido é o modo de operação principal dos processadores Intel modernos (a partir do 80286, consolidado no 80386). Nele, o sistema operacional controla o acesso à memória e protege processos uns dos outros.

Quando processadores de 64 bits operam no modo protegido (compatibilidade x86), eles têm estas características:

  • Endereços de 32 bits → espaço de endereçamento de 2³² = 4 GB
  • Registradores operam com 32 bits
  • Os registradores estão distribuídos em 3 grupos

Os 3 grupos de registradores no modo protegido:

  1. Registradores Gerais (EAX, EBX, ECX, EDX, etc.)
  2. Registradores de Deslocamento/Offset (EIP, ESP, EBP, ESI, EDI)
  3. Registrador de Flags (EFLAG)

Além disso, os seletores de segmento operam com 16 bits.

Formas de gerenciar o espaço de endereçamento:

MétodoComo funcionaQuando usado
SegmentaçãoA memória é dividida em blocos (segmentos) de tamanhos variadosSempre ativo no modo protegido
PaginaçãoA memória é dividida em páginas de tamanho fixo (tipicamente 4 KB)Opcional, gerenciado pelo SO — ver seção 19
Segmentação + PaginaçãoPrimeiro segmenta, depois paginaCombinação dos dois métodos

4.3 Registrador EFLAG

Cada bit desse registrador sinaliza algo sobre a última instrução executada. Os bits mais importantes:

BitSiglaSignificado
0CFCarry Flag — houve transporte (overflow) em unsigned
2PFParity Flag — número de bits 1 no byte baixo é par
6ZFZero Flag — resultado da operação foi zero
7SFSign Flag — resultado é negativo (bit de sinal = 1)
11OFOverflow Flag — houve overflow em signed
Os flags são usados em instruções de salto condicional (JE, JNE, JG, JL...). Exemplo: após um CMP, se os valores forem iguais, o ZF fica em 1, e o JE (Jump if Equal) usa esse flag para decidir se pula.

5. Endereçamento de Memória no Modo Protegido

Existem 3 tipos de endereçamento:

  1. Endereço Lógico (Virtual) = par (Seletor : Offset)
  2. Endereço Linear = Endereço base do segmento + Offset
  3. Endereço Físico = o endereço real na RAM

┌──────────────────────────────────────────────────────────┐ │ O ENUNCADO MENCIONA... │ │ │ │ "próxima instrução" / "buscar instrução" │ │ → EIP + CS │ │ │ │ "ler dado" / "buscar dado" / "operando de leitura" │ │ → ESI + DS (ou ES/FS/GS, depende do enunciado) │ │ │ │ "escrever" / "gravar" / "armazenar resultado" │ │ → EDI + ES (ou DS/FS/GS, depende do enunciado) │ │ │ │ "PUSH" / "empilhar" / "topo da pilha" │ │ → ESP + SS │ │ │ │ "POP" / "desempilhar" │ │ → ESP + SS (primeiro incrementa, depois le) │ │ │ │ "acesso à pilha" / "EBP" / "frame" │ │ → EBP + SS │ │ │ │ NÃO MENCIONA NADA ESPECÍFICO? │ │ → Pergunte: qual registrador de deslocamento aparece? │ │ Use a tabela de pares para descobrir o seletor │ │ (DS/ES/FS/GS funcionam com ESI e EDI) │ └──────────────────────────────────────────────────────────┘
Atalho mental para não errar:
  • EIP = Instruction Pointer → Código → CS
  • ESI = Source Index → Saída (origem) → Leitura → DS (ou ES/FS/GS)
  • EDI = Destination Index → Destino → Escrita → ES (ou DS/FS/GS)
  • ESP = Stack Pointer → Pilha (topo) → SS
  • EBP = Base Pointer → Pilha (base) → SS

Lembre-se: DS, ES, FS e GS são intercambiáveis — qualquer um deles pode trabalhar com ESI ou EDI. O enunciado da questão sempre diz qual seletor usar.

5.3 Exemplo Rápido de Identificação

Pergunta: "Dado um PUSH EAX, onde ESP = 0x00C00FF0, identifique os 5 passos."

Passo 1: O enunciado diz "PUSH" → operação de pilha → registrador = ESP

Passo 2: ESP trabalha com SS → vá à tabela de descritores e ache qual seletor é o de pilha

A partir daqui é só aplicar a fórmula: Linear = Base + ESP

Se o enunciado não diz explicitamente qual operação é, procure o nome do registrador que aparece no enunciado. Ex: se aparece ESI = 0x12345, automaticamente é leitura de dados. O seletor pode ser DS, ES, FS ou GS — o enunciado sempre diz qual.

6. Segmentos de Memória

Quando um programa é executado no modo protegido, o SO aloca segmentos na memória para ele:

TipoQuantidade por programaFunçãoTamanho
Código (CS) 1 apenas Armazena as instruções do programa 1 byte a 4 GB
Pilha (SS) 1 apenas Cálculos intermediários e troca de contexto 1 byte a 4 GB
Dados (DS, ES, FS, GS) Até 4 Armazena as variáveis do programa 1 byte a 4 GB cada
Por que separar? A separação permite que o SO aplique permissões diferentes a cada segmento. Por exemplo: o segmento de código pode ser "somente leitura" (não pode ser modificado), evitando que o programa corrompa suas próprias instruções.

7. Tabela de Descritores de Segmento

É a tabela que o SO usa para definir cada segmento na memória. Cada entrada (descritor) contém 4 campos:

TESTE DE SEGURANÇA: Toda vez que o endereço linear é calculado, ele é comparado com o endereço limite. Se endereço linear > endereço limite, ocorre GPF (General Protection Fault) — falha de proteção geral. O programa é abortado imediatamente.

Tamanho da Tabela de Descritores e Multitarefa:

  • Cada tabela de descritores de segmento tem 8 KBytes de tamanho
  • Existem várias tabelas de descritores na memória, definidas pelo SO
  • Isso permite que vários segmentos estejam definidos simultaneamente
  • Essa estrutura viabiliza a criação de sistemas operacionais multitarefa na arquitetura PC
  • Porém, apenas um processo por vez está sendo executado pelo processador (rodízio)
Na prova: Se perguntarem "por que a arquitetura Intel suporta multitarefa?", a resposta é: porque existem várias tabelas de descritores de 8KB cada, permitindo que múltiplos segmentos de múltiplos processos estejam definidos na memória ao mesmo tempo, com o SO rodiziando entre eles.

8. Processos e Escalonamento

Processo: É um programa que está em execução. Vários processos podem estar definidos na memória, mas apenas um por vez está sendo executado pelo processador.

Escalonamento: O SO decide qual processo usa o processador e por quanto tempo (rodízio / time-sharing).

Contexto de Hardware: É o conjunto de informações dos registradores internos do processador para um dado processo. Quando o processo é trocado:

  • O contexto do processo antigo é salvo no segmento TSS (Task State Segment) na memória principal
  • O contexto do novo processo é restaurado do TSS dele

Fórmula: Contexto do Processo = Contexto de Software + Contexto de Hardware

Quando o processo retoma, ele continua exatamente de onde parou.

9. Detalhamento dos Seletores e Registradores

9.1 CS : EIP (Código)

CS (Code Segment) — seletor de código. Identifica o segmento onde está o código do programa em execução.

EIP (Instruction Pointer) — armazena o endereço da próxima instrução a ser executada.

  • A cada instrução executada, o EIP é atualizado automaticamente (incrementado de 4 em 4 bytes na arquitetura 32 bits)
  • O EIP é um ponteiro: é inicializado pelo programa e alterado por saltos (JMP, CALL, RET)

9.2 SS : ESP (Pilha — Topo)

Registrador ESP (Extended Stack Pointer) — ponteiro de pilha.

  • Armazena o endereço lógico do topo da pilha
  • Na arquitetura Intel, a pilha cresce de cabeça para baixo (endereços decrescentes)
  • Empilhar (PUSH): o dado é colocado no endereço apontado por ESP, depois o ESP é pós-decrementado em 4 bytes
  • Desempilhar (POP): o ESP é pré-incrementado em 4 bytes, depois o dado é lido da nova posição
PILHA NA ARQUITETURA INTEL (cresce para BAIXO) Endereço alto (início da pilha) ┌─────────────┐ 0x00C01000 │ Dado 1 │ ├─────────────┤ 0x00C00FFC ← ESP apontava aqui antes do PUSH │ Dado 2 │ ├─────────────┤ 0x00C00FF8 │ Dado 3 │ ├─────────────┤ 0x00C00FF4 │ (vazio) │ ← ESP aponta para VAZIO (topo) └─────────────┘ 0x00C00FF0 Endereço baixo PUSH 5: 1. Coloca 5 no endereço 0x00C00FF0 2. ESP = ESP - 4 → agora ESP = 0x00C00FEC POP: 1. ESP = ESP + 4 → agora ESP = 0x00C00FF0 2. Lê o dado de 0x00C00FF0
Por que a pilha cresce para baixo? É uma convenção da arquitetura Intel. Isso significa que empilhar DECREMENTA o ESP e desempilhar INCREMENTA o ESP. Não confunda!

9.3 SS : EBP (Pilha — Base)

EBP (Extended Base Pointer) — ponteiro base de pilha.

É um ponteiro auxiliar que permite acessar dados dentro da pilha sem precisar desempilhar. É como uma "janela" fixa para olhar dentro da pilha.

Muito usado em frames de função: quando uma função começa, EBP salva o topo antigo da pilha e ESP desce para alocar espaço local. Assim, os parâmetros e variáveis locais ficam acessíveis via EBP com offset fixo.

9.4 DS/ES/FS/GS : ESI/EDI (Dados)

SeletorNomeFunção

ESExtra SegmentSegmento de dados extra
FS, GSExtra segmentsSegmentos de dados adicionais (usados pelo SO para TLS, etc.)

ESI (Source Index) — armazena o endereço de leitura de dados.

EDI (Destination Index) — armazena o endereço de escrita de dados.

Juntos, ESI e EDI são usados em instruções como MOVS (movimentar dados de um endereço para outro), onde ESI aponta para a origem e EDI para o destino.

10. Os 5 Passos da Execução de uma Instrução

QUANDO UM PROCESSADOR VAI EXECUTAR UMA INSTRUÇÃO, ESTES SÃO OS 5 PASSOS:

  1. Identificar os registradores de deslocamento
    De acordo com a instrução, identifica quais registradores de deslocamento (offset) ela utilizará. Ex: se é uma instrução de código, usará EIP; se acessa dados, usará ESI ou EDI.
  2. Identificar os seletores de segmento
    Identifica quais seletores de segmento estão associados aos registradores de deslocamento. Ex: se o offset é EIP, o seletor é CS; se é ESI, o seletor é DS.
  3. Calcular o endereço linear
    Localiza na tabela de descritores de segmento o endereço base correspondente ao seletor, e soma com o offset:
    Endereço Linear = Endereço Base do Segmento + Offset
  4. Teste de segurança (Limite)
    Compara o endereço linear com o endereço limite. Se linear > limite → GPF e o programa é abortado.
  5. Definir o endereço físico
    Se a paginação estiver desativada: endereço físico = endereço linear.
    Se a paginação estiver ativa: o endereço linear é traduzido usando tabelas de páginas para obter o endereço físico (ver seção 19).
Resumo visual: Seletor:Offset → Linear = Base + Offset → Teste do Limite → Físico → RAM

12. Glossário de Termos

GPF (General Protection Fault)
Falha de proteção geral. Ocorre quando o processador detecta uma violação de memória (endereço fora do limite, acesso não autorizado, etc.) e aborta o programa.
TSS (Task State Segment)
Segmento na memória onde o contexto de hardware de um processo é salvo quando ele é trocado pelo escalonador.
Contexto de Hardware
Conjunto de valores dos registradores internos do processador para um processo específico.
Contexto do Processo
= Contexto de Software + Contexto de Hardware. Representa todo o estado de um processo.
Escalonamento
Serviço do SO que decide qual processo executa e por quanto tempo (round-robin, prioridades, etc.).
Processo
Programa que está em execução. Quando definido na memória mas não está rodando, é chamado de "programa".
Endereço Lógico / Virtual
Par (Seletor : Offset) que representa o endereço "visto" pelo programa. Traduzido pelo hardware para endereço físico.
Segmentação
Técnica de dividir a memória em blocos de tamanho variável (segmentos), cada um com permissões próprias.
Paginação
Técnica de dividir a memória em páginas de tamanho fixo (tipicamente 4 KB) para gerenciamento eficiente.
Página
Pedacinho de 4 KB em que o processo é dividido na paginação.
Frame (Quadro de página)
Pedacinho de 4 KB da memória física onde uma página é colocada.
Memória Virtual (Mv)
Parte do HD reservada para se comportar como continuação da memória principal. Guarda as páginas do processo.
Remapeamento de endereço
Quando um endereço lógico passa a ocupar um endereço físico diferente durante a execução (a página voltou a um frame diferente).
Swap
Substituição de todas as páginas de um programa pelas de outro quando todos os frames estão ocupados.
Unidade de Paginação
Parte da arquitetura x86 (modo protegido) que, a partir do endereço linear (da segmentação), calcula o endereço físico por endereçamento multinível.
Tabela de Diretório
Tabela de 4 KB com 1024 entradas (4 bytes cada) que aponta para as tabelas de página. Seu endereço base fica no CR3.
Tabela de Página
Tabela de 4 KB com 1024 entradas (4 bytes cada) que aponta para as páginas (endereço físico base).
OFFSET da Página
Os 12 bits menos significativos do endereço linear; somado ao endereço da página (Epg) completa o endereço físico.
Ring (Anel)
Nível de privilégio no modo protegido. Ring 0 = kernel (máxima privilégio), Ring 3 = aplicativos (mínima).
Clock
Frequência do processador em Hz/MHz/GHz. Cada ciclo permite uma operação básica. Maior clock = mais operações/segundo (tudo o mais constante).
CPI (Cycles Per Instruction)
Número médio de ciclos de clock que uma instrução leva para executar.
ISA (Instruction Set Architecture)
Conjunto de instruções que um processador consegue executar. Define a compatibilidade binária entre processadores.
Modo de Compatibilidade
Submodo de 64 bits que roda programas de 32 bits. Usa apenas os 8 primeiros registradores (versão de 32 bits).
Explicit vs Implícito
Em PUSH/POP, o endereço "explícito" aparece na instrução (segmento de dados). O "implícito" está escondido no registrador ESP (segmento de pilha).
DST vs SRC
DST = destino, SRC = origem. Na sintaxe Intel o destino vem primeiro: MOV DST,SRC copia de SRC para DST.
Constante (#)
Operando com # ou entre aspas é um valor literal (constante). Sem #, é o conteúdo de um endereço na memória.
JUMP (salto)
Instrução que altera o fluxo de execução mudando o EIP. Incondicional: JMP. Condicional: Jxx (testa flags).
Jxx
Saltos condicionais: JE (=), JNE (≠), JG (>), JGE (≥), JL (<), JLE (≤). Usados logo após um CMP.
IN / OUT
Instruções de entrada/saída. IN AX,port lê do dispositivo para AX; OUT port,AX envia AX ao dispositivo.
MUL / DIV (implícitos)
MUL usa EAX implicitamente (EAX = EAX × SRC). DIV divide AX por SRC (AL = quociente, AH = resto). Não têm operando DST.

📌 Antes de tudo: o que é EAX? (aparece o tempo todo daqui pra frente)

Um registrador é uma "gaveta" de memória dentro do processador, onde o programa guarda valores na hora de calcular — fica muito mais perto da CPU do que a memória normal, por isso o código passa o tempo todo trazendo valores da memória para os registradores, calculando ali, e devolvendo para a memória.

  • EAX = a "gaveta" acumuladora de 32 bits — a principal para contas.
  • AX = a metade baixa do EAX (16 bits). AH / AL = as metades de 8 bits do AX (H = high, L = low).
  • Ela é implícita em certas instruções: a MUL multiplica sempre o EAX ("EAX = EAX × SRC"), a DIV divide o AX (quociente em AL, resto em AH), e o IN coloca o valor lido em AX.
  • Pra mostrar o número no monitor, o valor também passa por AX: OUT monitor, AX.

A mesma gaveta, 4 janelas diferentes (é assim que eu sei qual usar):

EAX (32 bits) = [ metade alta (16 bits) ][ AX (16 bits) ] AX (16 bits) = [ AH (8 bits) ][ AL (8 bits) ]

Registrador ≠ memória: MOV EAX, fatorial copia o valor que está na memória para a gaveta. MOV EAX, #5 coloca a constante 5 direto na gaveta (é o # que avisa: "isto é um número literal, não um endereço"). A seção 4.1/4.2 detalha todos os registradores — aqui basta saber o EAX.

E o "N" do professor, seria o AX? Não. O N é uma variável na memória — um endereço do segmento de dados com nome (a "caixinha N"). O AX é o registrador (a gaveta). Eles conversam pelo MOV: IN N, teclado guarda o digitado na caixinha N; MOV AX, N copia o conteúdo de N para a gaveta AX — isso é obrigatório porque MUL/DIV/OUT só sabem trabalhar com a gaveta, não direto com a memória; depois, MOV fatorial, EAX devolve pra memória.

16.1 — 1ª linha da 1ª tabela: MOV DST,SRC (o foco principal)

MOV DST, SRC → copia o valor de SRC para DST.

  • DST vem primeiro (sintaxe Intel). A direção é sempre SRC → DST.
  • SRC pode ser uma constante (com # ou aspas) ou o conteúdo de um endereço de memória.
  • Se o destino é um registrador: MOV EAX, 0000A14B copia para EAX o conteúdo do endereço 0000A14B (sem #, não é o número literal).
  • Não altera flags — só copia o dado.
Nas anotações do professor: MOV contador, #0 (inicializa contador com 0) e MOV EAX, 0000A14B (copia o valor da memória para EAX). O # marca constante — sem # é o conteúdo de um endereço.

EXEMPLO APLICADO — MOV na questão do fatorial:

Questão: "dado N, calcular o fatorial de N". A MUL multiplica sempre o EAX "por baixo dos panos", então o fluxo é: carregar no EAX → multiplicar → devolver para a memória.

0000 000C MOV fatorial, #1 <- inicializa: fatorial := 1 0000 0044 MOV EAX, fatorial <- carrega: EAX := fatorial 0000 0058 MOV fatorial, EAX <- guarda: fatorial := EAX (resultado da MUL)
  1. Linha 1 — inicializar: antes do laço, a variável fatorial passa a valer 1.
  2. Linha 2 — carregar: copia o valor da memória para o EAX (o fatorial continua 1 — o MOV só copiou).
  3. Linha 3 — guardar: depois de MUL contador (EAX = EAX × contador), copia o resultado de volta para fatorial.

Quando usar na prova: o MOV é o "entregador" — ele só copia SRC → DST, nunca calcula. Use para inicializar, carregar ou salvar.

Primeiro, o pré-requisito para não se perder: como ler 0101b

Um número em binário é uma fila de bits (dígitos 0 ou 1). Cada bit tem um valor, da direita para a esquerda: 1, 2, 4, 8 (sempre dobrando). O "b" no fim é só um aviso: "isto está em binário".

0101b = 0 × 8 + 1 × 4 + 0 × 2 + 1 × 1 = 4 + 1 = 5 bits: bit3 bit2 bit1 bit0

As posições têm nome: bit 0 (o da direita, vale 1), bit 1 (vale 2), bit 2 (vale 4), bit 3 (vale 8).

Agora a chave da sua pergunta: #1 escrito em 4 bits é 0001b. Por quê? Porque o número 1 só tem o bit 0 aceso (1×1 = 1); os bits 1, 2 e 3 ficam em 0. Então #1 = "um único bit aceso: o bit 0".

O MÉTODO — como TODAS as instruções BOOLEAN calculam, coluna por coluna:

As 4 instruções seguem a mesma rotina — só a regrinha de decidir cada bit é que muda. A rotina é:

  1. Escreva os dois números em binário, um em cima do outro, com a mesma quantidade de casas (os bits ficam alinhados em colunas).
  2. Vá coluna por coluna, da direita para a esquerda. Em cada coluna há um par de bits: o de cima (do EAX) e o de baixo (do operando).
  3. Aplique a regrinha da instrução naquele par e escreva o resultado (0 ou 1) na mesma coluna, na linha do resultado.
  4. Junte os 4 bits do resultado e leia o valor final.
As colunas são independentes: não existe "emprestar" nem "levar 1" como na soma. Um erro numa coluna não mexe nas outras.

Por que o bit 0 inverteu e os outros ficaram? O XOR pergunta em cada coluna: "esses dois bits são iguais?". Se iguais → 0; se diferentes → 1:

  • bit 3: 0 e 0 → iguais → 0
  • bit 2: 1 e 0 → diferentes → 1
  • bit 1: 0 e 0 → iguais → 0
  • bit 0: 1 e 1 → iguais → 0 (o bit 0 "alternou": era 1, virou 0)
Uso na prova: alternar/inverter um bit. E o truque famoso XOR EAX, EAX: todo bit é igual a ele mesmo → tudo dá 0 → zera o registrador (mais rápido que MOV EAX, #0).

▸ NOT — regra: "cada bit troca" (0 vira 1, 1 vira 0):

Atenção — é a única sem 2º número: ela só inverte cada bit do EAX:

  • bit 3: era 0 → vira 1
  • bit 2: era 1 → vira 0
  • bit 1: era 0 → vira 1
  • bit 0: era 1 → vira 0

Resultado: 1010b = 10.

Memorize: AND = "os dois têm que querer"; OR = "basta um querer"; XOR = "têm que ser diferentes"; NOT = "inverte tudo".

A tabela fiel mostra o formato teórico (IN AX, porta), mas nas questões resolvidas o professor troca o AX pelo nome da variável que aquele dado representa: IN N, teclado = "lê do teclado e guarda em N"; OUT monitor, contador = "mostra o valor de contador". Tudo o que o professor faz em laços é: teste sempre com CMP + JUMP condicional.

Repare: IN aparece no começo, OUT no fim, a comparação no meio e os saltos fazem o "vai e volta". Toda questão de fluxograma segue esse padrão.

Cada volta o teste pergunta "contador já alcançou ou passou de N?". Só quando a resposta é sim o JGE sai do laço.

16.5 — Jxx: qual usar depois de um CMP A, B

Depois do CMP A, B (que fez A − B):

Quero pular quando...UsoFlag que confirma
A é igual a BJEZF = 1 (subtração deu zero)
A é diferente de BJNEZF = 0
A > B (com sinal)JGZF = 0 e SF = OF
A ≥ BJGESF = OF (ou ZF = 1)
A < B (com sinal)JLSF ≠ OF
A ≤ BJLEZF = 1 ou SF ≠ OF
Regra prática: para igualdade use JE/JNE (não importa o sinal). Para maior/menor, o professor usa JG/JGE/JL/JLE como se fossem ">, ≥, <, ≤". Memória de bolso: JGE = "Jump se o primeiro for ≥ o segundo".
Na prática — como escolher o Jxx direto do texto da questão:
  • "Repita até o contador = N" (Exemplo 1, com INC de 1 em 1) → CMP N, contador + JNE (volta enquanto não for igual).
  • "Enquanto contador < N, some" → sai quando contador ≥ N → CMP contador, N + JGE (Exemplo 2).
  • "Se for par, mostra 0; senão ímpar, mostra 1" → testa o resto: CMP AH, #0 + JE par (18.4).
Método mastigado em 3 passos (fazendo uma questão de verdade):

Questão: "enquanto contador < N, some o incremento; quando contador ≥ N, mostre e pare."

  1. Escreva a condição de CONTINUAR (o que o laço faz): contador < N.
  2. Escreva a condição de SAIR (o contrário): contador ≥ N.
  3. Traduza a saída em "pular quando..." com o CMP na mesma ordem:
    CMP contador, N ; primeiro o contador (= A), depois o N (= B) --> A - B JGE fim ; pula quando contador >= N (a condição de sair)
    Por que JGE? Porque a saída é "≥", e JGE = "jump if greater or equal". Se a saída fosse "=" usaríamos JE; se fosse "<", JL. O Jxx sai com a condição de SAIR, não a de continuar.

17. Controle de Fluxo — JUMP, CMP e Constantes

Estas anotações vêm do bloco de notas do professor. Todo o material de estruturas de repetição (while / do while) e seleção (if / then / else) é montado com JUMP + CMP.

17.1 JUMP Incondicional

O JUMP incondicional é aquele que, ao ser executado, altera a sequência do fluxo de instruções de forma OBRIGATÓRIA — ou seja, sempre pula, sem perguntar nada.

Formato: JUMP DST (opcode de 4 bytes + destino de 4 bytes)

JUMP DST |---------|---------| 4 bytes | 4 bytes | v DST = endereço lógico do segmento de CÓDIGO para onde ocorrerá o salto
  • DST representa um novo valor do registrador EIP.
  • O salto pode ocorrer para um endereço posterior (para frente) ou anterior (para trás) — é assim que se "volta" num laço.

17.2 JUMP Condicional (2 instruções)

O JUMP condicional é implementado com 1 comparação + 1 salto:

PassoInstruçãoO que faz
1ºCMP END1, END2Compara o conteúdo de 2 endereços do segmento de dados, ou 1 endereço com uma constante.
2ºJxx DSTTesta o resultado da comparação (flag). Verdadeiro → salta para DST. Falso → executa a próxima instrução.

Formatos (cada campo tem 4 bytes):

Comparação (dados): |---------|---------|---------| CMP END1 END2 ; END1 e END2 no segmento de dados Salto (código): |---------|---------| Jxx DST ; DST = endereço de destino do salto

17.3 Constante: # ou aspas

OBS: se o operando tiver # ou estiver entre aspas, é uma constante (valor literal). Sem #, é o conteúdo de um endereço de memória.

Exemplo do bloco de notas (comparação com constante):

CMP #0000A14B, 00B2A000 ; compara a CONSTANTE 0000A14B com o conteúdo do endereço 00B2A000 JGE 0000A14B ; se a condição for verdadeira, salta para 0000A14B (segmento de código) MOV EAX, 0000A14B ; copia o valor do endereço 0000A14B para EAX
  • #0000A14B = o valor literal 0000A14B é a constante da comparação.
  • 00B2A000 (sem #) = endereço de dados, usamos o conteúdo dele.
  • O JGE salta para o endereço de código 0000A14B — o destino de um salto é sempre no segmento de código.

17.4 Exemplo 1 — Contador até N (Do While com JNE)

Enunciado: ler N via teclado, incrementar um contador de 1 em 1 até chegar em N, e exibir o contador.

0000 0000 IN N, teclado 0000 000C MOV contador, #0 0000 0018 INC contador 0000 0020 CMP N, contador 0000 002C JNE 0000 0018 0000 0034 OUT monitor, contador
Como saber o endereço da PRÓXIMA instrução (regra de ouro):

Cada pedaço ocupa 4 bytes: 4 bytes para a própria instrução + 4 bytes por operando. Basta contar os operandos:

  • 1 operando (ex.: INC contador, JMP 0000 0024) → 2 pedaços → 2×4 = 8 bytes → some +8 no endereço (em hexadecimal escreve-se +0x8).
  • 2 operandos (ex.: IN N, teclado, CMP N, contador) → 3 pedaços → 3×4 = 12 bytes → some +12 no endereço (em hexadecimal escreve-se +0xC).

Muito importante: os endereços estão em hexadecimal. Por isso 8 é escrito 0x8 e 12 é escrito 0xC.

Vendo na memória (cada célula = 4 bytes):

0000 0000 | IN | instrução 0000 0004 | N | operando 1 0000 0008 | teclado | operando 2 0000 000C | MOV | próxima instrução (0000 + 0C = 000C)

Detalhando um salto de endereço — de 0000 000C para 0000 0018:

A instrução em 0000 000C é MOV contador, #0, que tem 2 operandos.

  1. Quanto ela ocupa? 2 operandos → 12 bytes.
  2. Onde ela começa? Em 000C.
  3. Onde começa a próxima? Em 000C + 12.
  4. Converta para decimal (facilita): 000C = 12 → 12 + 12 = 24.
  5. Volte para hexadecimal: 24 = 18 → próxima em 0000 0018.

Por que 24 vira 18? Hexadecimal é base 16 (conta até F, não até 9):

0x0F = 15 0x10 = 16 0x11 = 17 0x12 = 18 0x13 = 19 0x14 = 20 0x15 = 21 0x16 = 22 0x17 = 23 0x18 = 24 ← é aqui!

Ou pelo "vai 1": C + C → C = 12, então 12 + 12 = 24. Um dígito hexadecimal só vai até 15, então 24 = 16 + 8 → escreve 8 e "vai 1" para a esquerda → 18.

Macetes para não errar:
  • Conte os operandos e pronto: 1 operando → +0x8; 2 operandos → +0x0C.
  • Quem tem 1 operando: os saltos (JMP, JNE, JE, JGE...) e INC/DEC. O resto (IN, MOV, CMP, ADD, OUT) tem 2.
  • Letras do hexadecimal: A=10, B=11, C=12, D=13, E=14, F=15.
  • Passou de 15? Tire 16 e "vai 1" para a esquerda (ex.: C+C = 24 = 16+8 → 18).
  • Na dúvida, converta: passe o endereço para decimal, some o tamanho e volte para hexadecimal.

Agora o "porquê" de cada instrução — pense no programa como uma receita:

  • IN = pegar o ingrediente: lê um valor do teclado.
  • MOV = guardar num pote: coloca um valor numa variável (ex.: contador = 0).
  • CMP = comparar duas coisas (não muda nada, só prepara a decisão do losango).
  • JGE / JNE = "se acontecer X, pule para tal lugar" (a decisão do losango vira um salto condicional).
  • JMP = "volte para o começo", sem condição — é o que fecha o loop.
  • INC / ADD = somar 1 ou um valor (o retângulo de processo).
  • OUT = servir o prato: mostra o resultado no monitor.
Por que isso cai na prova: o professor dá um fluxograma e pede o código correspondente, ou dá o código e pergunta "o que cada faixa de endereço representa?". A divisão é sempre: instrução (4 bytes) + operando 1 (4 bytes) + operando 2 (4 bytes).

17.4.1 Como descobrir para onde um salto aponta (código, tabela e fluxograma)

Todo salto (JMP, JNE, JGE...) leva o programa para o endereço escrito do lado dele. Mas "para onde isso é" só se descobre olhando o resto do código. Use os 3 passos:

  1. Monte a tabela de endereços: liste as instruções em ordem e calcule o endereço de cada uma (+0x8 se tiver 1 operando, +0x0C se tiver 2).
  2. Pegue o número do salto (ex.: 0000 0018).
  3. Procure esse número na coluna de endereços: a instrução que começa nele é o destino.

Exemplo 1 — encontrando o alvo do JNE:

0000 0000 IN N, teclado 0000 000C MOV contador, #0 0000 0018 INC contador ← é aqui que o JNE cai 0000 0020 CMP N, contador 0000 002C JNE 0000 0018 0000 0034 OUT monitor, contador

JNE 0000 0018 → procuro 0018 na tabela → é o INC contador. Logo: enquanto NÃO for igual, volta a incrementar.

Exemplo 2 — encontrando os alvos do JMP e do JGE:

0000 0024 CMP N, contador ← alvo do JMP 0000 0030 JGE 0000 003C 0000 0038 ADD contador, incremento 0000 0044 JMP 0000 0024 0000 004C OUT monitor, incremento
  • JMP 0000 0024 → procuro 0024 → é o CMP N, contador (o teste). É a volta do loop.
  • JGE 0000 003C → procuro 003C → não existe instrução começando em 003C (o ADD vai de 0038 a 0043). Por isso está errado; a saída do loop seria 0000 004C (o OUT).

O que preciso saber/entender para achar o alvo:

  • Os endereços estão em hexadecimal.
  • Endereço da próxima instrução = atual +0x8 (1 operando) ou +0x0C (2 operandos).
  • O alvo de um salto sempre cai no início de uma instrução — nunca no meio dela.
  • JMP salta sempre (fecha o loop). JNE/JGE/JE só saltam se a condição for verdadeira (decisão do losango).

Como achar na tabela: procure o número do salto na coluna Endereço — a instrução daquela linha é o destino.

Como achar no fluxograma: cada salto é uma seta:

  • JMP = a seta de volta do loop (retorna ao teste/incremento).
  • JNE/JGE = um dos ramos do losango (SIM ou NÃO), conforme a condição.

Sinal de erro: se o número do salto cair no meio de uma instrução, o alvo está errado.

  4. JGE 0000 004C → sai do laço quando contador ≥ N (ramo NÃO do fluxograma) e pula diretamente para o primeiro OUT, em 004C.
  5. ADD contador, incremento → acumula o incremento no contador (ramo SIM do fluxograma).
  6. JMP 0000 0024 → volta para o teste (repetição).
  7. OUT monitor, contador e OUT monitor, incremento → exibem os dois valores de saída do fluxograma: o Contador final (acumulado) e o Incremento (o passo que foi somado a cada volta).

⚠ Por que o código usa CMP contador, N + JGE?

O fluxograma descreve um laço "enquanto contador < N" — o programa sai do laço quando contador ≥ N. Pela regra da seção 16: CMP A, B; JGE pula quando A ≥ B. Para o JGE pular "quando contador ≥ N", o operando A precisa ser o contador: CMP contador, N.

Com CMP N, contador; JGE (como estava no bloco de notas), o teste ficaria N ≥ contador — a ordem invertida, que não bate com "sai quando contador < N". Daí a correção no código acima.

  • CMP contador, N → faz contador − N.
  • JGE salta quando contador ≥ N → exatamente "sai quando NÃO é (contador < N)".
  • Se contador < N, executa ADD e JMP de volta ao teste (continua o While).
  • Por que dois OUT? O bloco de saída do fluxograma mostra dois valores — Contador e Incremento: o resultado do laço é "o contador acumulado" e "o passo que foi somado a cada volta". Então o programa precisa de um OUT para cada valor. No bloco de notas as duas linhas vieram iguais (incremento, incremento) — provavelmente um erro de cópia: pelo fluxograma o primeiro OUT deve ser OUT monitor, contador.
Regra universal para a prova: decida primeiro o que o fluxograma quer dizer ("sai quando contador ≥ N"), depois escreva o CMP com o operando A primeiro e escolha o Jxx. Se a questão pedir o código exatamente como o professor anotou, mantenha CMP N, contador + JGE como ele escreveu — a resolução por CMP contador, N é a interpretação que segue o fluxograma.

17.7 Estruturas: repetição (While / Do While) e seleção (IF / THEN / ELSE)

OBS do bloco de notas: o JUMP condicional é usado para implementar:

  • Repetições: While (testa antes, Jxx no topo) e Do While (testa depois, Jxx no fim).
  • Seleções: IF THEN ELSE e IF THEN ELSE NULO (sem o ELSE).
O teste é SEMPRE feito com CMP + JUMP condicional. Nunca há teste sem CMP nos exercícios do professor.

18.2 — Questão 1: Fatorial de N (lido via teclado)

18.3 — Questão 2: N primeiros termos da sequência de Fibonacci

Enunciado: "Calcule os N primeiros termos da sequência de Fibonacci, sabendo que os dois primeiros termos são 0 e 1, e o próximo termo é formado pela soma dos dois últimos."

Raciocínio: guardamos os dois últimos termos. A cada volta, o novo termo = termo1 + termo2 (usando ADD). Depois "andamos": o termo1 recebe o termo2, e o termo2 recebe a soma. Repetimos até produzir N termos.

0000 0000 IN N, teclado ; quantos termos 0000 000C MOV t1, #0 ; termo 1 (0) 0000 0018 MOV t2, #1 ; termo 2 (1) 0000 0024 MOV contador, #2 ; já temos 2 termos mostrados 0000 0030 CMP N, contador ; teste: N - contador 0000 003C JLE 0000 0084 ; se N <= contador -> sai do laço (pula pro OUT) 0000 0044 MOV EAX, t1 ; prepara a soma 0000 0050 ADD EAX, t2 ; próximo = t1 + t2 0000 005C MOV t1, t2 ; termo1 "anda" 0000 0068 MOV t2, EAX ; termo2 = novo termo 0000 0074 INC contador ; conta mais um termo 0000 007C JMP 0000 0030 ; volta ao teste (é o laço) 0000 0084 OUT monitor, t2 ; última instrução: mostra o último termo calculado

Endereços na mesma regra do professor (1 operando → +0x8; 2 operandos → +0x0C): JLE 0000 0084 (= 132) vai para o OUT final; JMP 0000 0030 (= 48) volta para o teste.

Sequência para N = 5: 0, 1 → t1=0,t2=1 → próximo=1 → t1=1,t2=1 → próximo=2 → t1=1,t2=2 → próximo=3 → t1=2,t2=3 → último termo = 3 (sequência 0,1,1,2,3). ✓

Chave: os três MOV no fim do laço deslocam os termos (o "andar da sequência"). Respeite a ordem: primeiro calcula a soma, depois desloca.

18.4 — Questão 3: Identificar se N é par ou ímpar (usa DIV)

Enunciado: "Dado N números, identifique se o número é par ou ímpar."

Raciocínio: dividimos N por 2. Se o resto (AH) = 0 → par; se resto = 1 → ímpar. É a aplicação direta do DIV da tabela (AL = quociente, AH = resto).

0000 0000 IN N, teclado ; lê o número 0000 000C MOV AX, N ; AX = dividendo 0000 0018 MOV BL, #2 ; divisor = 2 (BL é um registrador auxiliar) 0000 0024 DIV BL ; AL = quociente, AH = resto 0000 002C CMP AH, #0 ; teste: resto = 0? 0000 0038 JE 0000 0054 ; se par -> salta pro OUT do par (bloco THEN) 0000 0040 OUT monitor, #1 ; ímpar: mostra 1 (bloco ELSE, cai aqui) 0000 004C JMP 0000 0060 ; fim do ELSE: pula o OUT do par (fim do programa) 0000 0054 OUT monitor, #0 ; par: mostra 0 (última instrução do programa)

Endereços na mesma regra do professor: JE 0000 0054 (= 84) → bloco par; JMP 0000 0060 (= 96) → endereço logo após o último OUT (= fim do programa). O JMP 0000 0060 é o "não pode cair no bloco do par": sem ele, depois de mostrar o 1 o programa continuaria e mostraria o 0 também. É o fim do THEN que a estrutura IF, THEN, ELSE do professor exige (Obs dele: o JUMP também serve para IF, THEN, ELSE).

Obs. importante: o DIV destrói o dividendo — o valor que estava em AX é sobrescrito por AL (quociente) e AH (resto). Por isso o teste é feito com AH logo após o DIV; qualquer valor anterior em AX se perde.

Testando N = 7: MOV AX,7 → MOV BL,#2 → DIV BL → AL = 3, AH = 1 → CMP AH,#0 → JE não salta → mostra 1 (ímpar) → JMP 0000 0060 termina. ✓   N = 4: AH = 0 → JE 0000 0054 salta → mostra 0 (par). ✓

Frase "mastigada": par é quando resto 0; ímpar quando resto 1. Para N números, esse bloco fica dentro de um laço comandado por um contador.

18.5 — Molde IF / THEN / ELSE (questão de seleção)

Estrutura IF condição THEN bloco-A ELSE bloco-B:

CMP X, Y ; testa a condição Jxx else_label ; SE a condição for FALSA, pula para o ELSE ... instruções do bloco A (THEN) ... JMP fim_if ; termina o THEN para não cair no ELSE else_label: ... instruções do bloco B (ELSE) ... fim_if: ...

IF / THEN / ELSE nulo = idem, mas sem o bloco B (o rótulo else_label aponta direto para fim_if).

  • Na escrita do código, o salto do "fim do THEN" usa um JMP incondicional (para pular o ELSE).
  • O teste da condição usa CMP + Jxx (condicional).
Traduzindo para o formato do professor (com endereços): O "rótulo" fim_if não é escrito na prova — é o endereço logo após a última instrução. Exemplo real da questão 18.4: o JMP 0000 0060 pula o bloco do par e vai direto para o fim do programa (não há instrução além do último OUT).

18.6 — Questões práticas com BOOLEAN (proposta do guia)

Sobre esta seção: o professor não resolveu BOOLEAN no bloco de notas (a questão de par/ímpar dele usa DIV). Estas resoluções são propostas deste guia no mesmo formato dele — mesma regra de endereços, programa termina no último OUT.

A regra de ouro antes de tudo:

Toda instrução BOOLEAN faz DST = DST [op] SRC — o resultado vai para o primeiro operando. Por isso a sequência padrão numa questão é sempre:

IN N, teclado ; 1) entra o dado MOV EAX, N ; 2) traz pro EAX (é ele que o BOOLEAN vai alterar) AND EAX, #1 ; 3) a instrução em si [AND / OR / XOR / NOT] CMP ... Jxx ... ; 4) só se a questão pedir decisão (ex.: o AND do par/ímpar) OUT monitor, EAX ; 5) mostra o resultado; programa termina aqui

E as regras do professor pra qualquer programa: teste sempre com CMP + Jxx; o programa termina no último OUT (nada de "JMP pro fim" que caia em endereço vazio).

▸ AND — "o número é par ou ímpar?"

Enunciado: "Dado N, identifique se é par ou ímpar, analisando o bit 0."

▸ OR — "ligar um bit à força"

Enunciado: "Antes de mostrar o número, o bit 3 (que é um aviso, vale 8) deve estar SEMPRE ligado, mesmo que o resto não mude."

Raciocínio: OR EAX, #8 — o #8 = 1000b tem 1 só no bit 3, e o OR liga "se qualquer um for 1". Resultado: bit 3 vai pra 1, o resto fica intacto.

0000 0000 IN N, teclado ; lê o número 0000 000C MOV EAX, N ; copia pro EAX 0000 0018 OR EAX, #8 ; liga o bit 3 à força (2 operandos -> +0x0C) 0000 0024 OUT monitor, EAX ; mostra já com o aviso ligado (última instrução)

Testando N = 5: 0101b OR 1000b = 1101b = 13. O número "mudou"? Sim — mas a questão só queria o bit 3 aceso; nenhum outro bit foi tocado.

▸ XOR — "alternar um bit a cada leitura"

Enunciado: "A cada leitura do teclado, o bit 0 deve alternar (de 0→1, de 1→0)."

Raciocínio: o XOR responde em cada coluna "os dois bits são iguais?" — iguais dão 0, diferentes dão 1. Como o #1 tem 1 só no bit 0, esse bit inverte e o resto fica intacto.

0000 0000 IN N, teclado ; lê o número 0000 000C MOV EAX, N ; copia pro EAX 0000 0018 XOR EAX, #1 ; alterna o bit 0 0000 0024 OUT monitor, EAX ; última instrução

Testando duas leituras: 1ª: N = 5 (0101b) → XOR EAX,#1 → 0100b = 4 (era 1, virou 0). 2ª: N = 4 (0100b) → 0101b = 5 (era 0, voltou a 1). Por isso "alterna". E o truque: XOR EAX, EAX zera o registrador (todo bit é igual a si mesmo → tudo dá 0).

▸ NOT — "inverter todos os bits"

Enunciado: "Inverta todos os bits de N antes de mostrar."

Raciocínio: NOT só troca cada bit (0→1, 1→0). Atenção: é a única com 1 operando — o endereço anda +0x08, não +0x0C.

0000 0000 IN N, teclado ; lê o número 0000 000C MOV EAX, N ; copia pro EAX 0000 0018 NOT EAX ; 1 operando -> +0x08 0000 0020 OUT monitor, EAX ; mostra invertido (última instrução)

Conferindo: MOV em 000C (+0x0C) → NOT em 0018 (+0x08) → OUT em 0020. Testando N = 5: 0101b → 1010b = 10. Ele não soma nem multiplica — cada bit apenas troca.

Frase "mastigada" pra revisão rápida: AND = "os dois têm que ser 1" (lê um bit, ex. par/ímpar); OR = "basta um ser 1" (liga bit à força); XOR = "iguais dão 0" (alterna bit); NOT = "inverte tudo" (1 operando!). Se a questão for "par ou ímpar" e você lembrar só de um jeito de resolver, lembra do 18.4 (DIV) — ele também resolve.

19. Paginação (Gerenciamento de Memória) — Assunto de Prova

Tudo desta seção veio do bloco de notas do professor — é assunto de prova. Paginação é a técnica de gerenciamento de memória (usada no modo protegido) que divide o processo e a memória física em pedaços iguais de 4 KB, fazendo a memória caber mesmo com espaço físico limitado. Leia com calma: cada parágrafo do professor vira pergunta de prova.

19.1 — Por que a paginação existe? (o problema que ela resolve)

A memória física tem tamanho limitado. Sem a paginação, quando um processo vai ser executado ele precisa de um espaço contíguo livre na memória física; se não existir memória disponível para alocar o processo, o sistema operacional informa que não existe memória disponível e o processo não é executado.

Com a paginação, o cenário muda:

  • O processo a ser executado é dividido em tamanhos iguais de 4 KB → cada pedaço é uma página.
  • A memória física disponível também é dividida em tamanhos iguais de 4 KB → cada pedaço é um frame ou quadro de página.

Ou seja: o processo não precisa caber inteiro na RAM. Ele vai sendo trazido página a página — só o que está em uso fica carregado.

19.4 — Como funciona: o ciclo de vida da página (mastigado):

  1. Processo dividido: o processo é quebrado em várias páginas de 4 KB e armazenado na memória virtual (HD).
  2. Cópias para a RAM: somente algumas das páginas do processo são copiadas para os frames disponíveis da memória principal.
  3. Página requisitada e ausente: durante o processamento, se for feita referência a uma página que não está em nenhum frame, a página referenciada deve ser trazida para um dos frames.
  4. Substituição (se não tiver frame livre): a página nova sobrescreve a página anterior que estava carregada no frame.
  5. Página alterada volta primeiro (preciosa!): se a página que será substituída tiver sido alterada, antes de ser sobrescrita ela é enviada de volta para a memória virtual (para não perder as mudanças).
  6. Pode voltar a outro lugar: durante a execução, uma página já retirada pode ser requisitada novamente; ao ser trazida para a RAM, ela pode ocupar um frame diferente do anterior → isso é o remapeamento (item 19.5).
Resumo de prova: RAM só tem os frames; HD (memória virtual) guarda tudo. Página ausente → busca da memória virtual. Frame ocupado → sobrescreve o antigo. Página antiga alterada → salva antes na memória virtual.

19.5 — Remapeamento de endereço (exemplo do bloco de notas):

Um endereço lógico pode ocupar endereços físicos diferentes ao longo da execução. É exatamente isso no exemplo do professor — o mesmo programa (4 instruções) é carregado na memória em bases físicas diferentes:

Endereço lógico do programa (o mesmo nas duas execuções):

0000 0020 (próxima instrução) 0000 0014 ADD total, END2 0000 000C INC END2 0000 0000 MOV END1, END2

Execução 1 — colocado na memória física em 00bf:

00bf 0020 00bf 0014 ADD total, END2 00bf 000c INC END2 00bf 0000 MOV END1, END2

Execução 2 — se executado de novo, o endereço PODE mudar (aqui foi para af10):

af10 0020 af10 0014 Add total, END2 af10 000c Inc END2 af10 0000 mov END1, END2

Mastigando: o MOV tem endereço lógico 0000 0000. Na 1ª execução ele morou no físico 00bf 0000; na 2ª execução morou no físico af10 0000. Mesmo endereço lógico, endereços físicos diferentes → remapeamento de endereço. O OFFSET final (últimos dígitos 0000/000C/0014/0020) se mantém: ele é interno à página; o que muda é a base física onde a página foi carregada.

Correção feita por este guia: no bloco de notas o professor trocou INC e ADD nas colunas físicas (escreveu ADD no offset 000C e INC no 0014). Como o offset é fixo, o 000C tem de ser INC e o 0014 ADD — a correção acima acompanha o código lógico.

19.6 — Swap (troca completa de programas):

Obs do professor: quando um programa vai ser executado e todos os frames da memória já estão ocupados por páginas de outro programa, é necessário fazer a substituição de todas as páginas de um programa pelas páginas do programa que será executado — essa operação recebe o nome de swap.

Diferença que cai na prova: fetch individual de página (19.4) substitui uma página quando ela é requisitada. Swap (19.6) troca o programa inteiro quando não há nenhum frame livre para o novo processo.

19.7 — Como o x86 (modo protegido) calcula o endereço físico — a conta 10 | 10 | 12:

A paginação do x86 no modo protegido é implementada pela unidade de paginação: a partir do endereço linear (que foi calculado pela unidade de segmentação), ela calcula o endereço físico. O cálculo usa um sistema de endereçamento multinível:

  • Nível 1 e 2: usados na tabela de diretório — ela aponta para a tabela de página (nível 3).
  • Nível 3: a tabela de página aponta para a página, que tem o endereço físico.

O endereço linear (32 bits) é dividido em 3 partes:

  3. Cada página também possui 4 KB.
Confira a conta (é por isso que tudo é 4 KB): 1024 entradas × 4 bytes = 4096 bytes = 4 KB. A tabela de diretório tem 1024 entradas de 4 bytes, a tabela de página também, e por isso elas ocupam exatamente uma página (4 KB) cada.

Por que a divisão é 10 | 10 | 12?

Um endereço de 32 bits (8 dígitos hexadecimais) é cortado em três pedaços que somam 32 bits:

  • 10 bits para o índice do diretório → 210 = 1024 linhas no mapa-mestre;
  • 10 bits para o índice da página → 210 = 1024 linhas na tabela de páginas;
  • 12 bits para o offset → 212 = 4096 bytes = 4 KB, que é o tamanho de uma página (e de um quadro).
Segredo do "×4": cada linha das tabelas guarda um número de 32 bits = 4 bytes. Então a linha de número N fica no endereço base + N × 4. Multiplicar por 4 é só empurrar 2 bits para a esquerda (acrescentar dois zeros no fim do número binário). É por isso que 107 × 4 = 0x1AC e 897 × 4 = 0xE04.

As três zonas do desenho

Zona 1 — a conta (esquerda): é o caminho do endereço passo a passo: CR3 → EETDIR → lê ETP → EETPG → lê PÁGINA → soma o offset → endereço físico. Cada seta significa "somei o índice×4 e fui ler lá".

Zona 2 — a árvore (meio): é o mesmo caminho visto como estrutura. O nó de cima é o registrador CR3 apontando para a TABELA DE DIRETÓRIO (1024 entradas). Uma dessas entradas (a de índice 107) aponta para a TABELA DE PÁGINAS (1024 entradas). Uma dessas (índice 897) aponta para a PÁGINA de 4 KB. Os "1024" ao lado dos grupos são o número de ramos de cada nível.

Zona 3 — a coluna de memória (direita): é a RAM de 4 GB como uma régua que cresce para baixo. Nela você vê, na ordem em que aparecem os endereços, os blocos: 000B 0000 (a tabela de diretório), 0022 0000 (a tabela de páginas) e 0130 0000 (a página de 4 KB, hachurada em vermelho). As etiquetas 210...4KB dizem o tamanho de cada bloco, e as setas ligam cada bloco ao seu lugar na conta.

Como não se perder: leia sempre de cima para baixo e de esquerda para a direita. Os três endereços importantes aparecem em ordem crescente — 000B 0000 < 0022 0000 < 0130 0000 — que é exatamente a ordem em que são visitados.

20.4 — A pergunta do professor, do começo ao fim (método completo)

Enunciado do professor: "Se uma determinada página, durante a paginação, for carregada em 2 quadros de página anteriores ao que estava, quais as alterações que devem ser feitas no seu exemplo no cálculo da paginação?"

Antes da conta, a ideia com desenho mental: imagine a memória RAM como uma rua comprida de casinhas, todas do mesmo tamanho (4 KB). Cada casinha é um quadro. A página (o dado) é uma família que mora em uma dessas casas — no exemplo, na casa que começa em 0130 0000. O endereço linear é só o nome da família ("quero a Mamãe"), e o endereço físico é o número da casa.   • Somar hexa: alinhe os blocos pela direita e some casa a casa; se passar de F, "vai um" para a esquerda.

Q5. Agora mude outra coisa: quem se mudou de lugar foi a tabela de páginas, de 0022 0000 para 0023 0000 (e a página do dado continua em 0130 0000). O que muda no cálculo?

▶ Ver resolução

Ideia em 1 frase: mover a tabela muda onde eu leio — mas o dado final pode ficar igual.

Passo 1 — o que muda primeiro: o conteúdo lido no EETDIR (a ETP) passa de 0022 0000 para 0023 0000. O EETDIR em si (000B 01AC) não muda — continua sendo o mesmo lugar no diretório.

Passo 2 — novo EETPG: 0023 0000 + 897×4 = 0023 0000 + 0xE04 = 0023 0E04.

Passo 3 — o conteúdo lido ali: a questão diz que a página continua em 0130 0000, então Epg = 0130 0000.

Passo 4 — endereço físico: 0130 0000 + 0xD74 = 0130 0D74 — igual ao original!

Lição de prova: mover a tabela = mudar o caminho (endereços de leitura). Mover a página = mudar o destino (endereço físico). São coisas diferentes — não confunda!

Nível 3 — combinações e pegadinhas de prova

Q6. Combinação: a tabela de páginas passa para 0023 0000 e a página desce 3 quadros. Recalcule Epg, EETPG e endereço físico.

▶ Ver resolução

Passo 1 — a tabela mudou: EETPG = 0023 0000 + 897×4 = 0023 0000 + 0xE04 = 0023 0E04.

Passo 2 — a página desceu 3 quadros: 3 × 0x1000 = 0x3000 → 0130 0000 − 0x3000 = 012F D000.

Passo 3 — endereço físico: 012F D000 + 0xD74 = 012F DD74.

Resposta: Epg 012F D000; EETPG 0023 0E04; físico 012F DD74 ✓

Repare que as duas mudanças são independentes: uma mexe no passo 2 (a tabela) e a outra no passo 3 (a página).

Q7. (pegadinha) Quando a página é movida de quadro, o endereço linear 1AF81D74 muda? E o programa que está rodando percebe alguma coisa?

▶ Ver resolução

Resposta curta: Não e não.

Por que o endereço linear não muda: ele é como o nome que o programa usa ("quero o byte X"). Esse nome não depende de onde o dado está fisicamente guardado na RAM.

Por que o programa não percebe: quem sabe o endereço real é a tabela de páginas, e quem a atualiza é o sistema operacional. A tradução linear → físico é transparente: o programa roda igual, sem mudar uma linha de código.

Analogia: você salvou o contato "Mamãe" no celular. Se sua mãe se mudar de casa, você continua discando "Mamãe" — o número por trás é que foi trocado na agenda.

Q8. (pegadinha) Por que não dá para mover a página "meia página" (2 KB) em vez de 4 KB?

▶ Ver resolução

Por que não: a unidade de alocação é o quadro inteiro (4 KB), e a entrada da tabela guarda só a base da caixa — os 12 bits de baixo são sempre zero.

O que decide "onde dentro da caixa": o offset, que tem 12 bits e cobre de 0x000 até 0xFFF (exatamente 4 KB).

Analogia: é como uma prateleira com gavetas fixas do mesmo tamanho — você guarda objetos dentro das gavetas, não "meia gaveta".

Se você movesse para um endereço que não fosse múltiplo de 4 KB, os 12 bits baixos da base deixariam de ser zero e a tradução quebraria.

Q9. (raciocínio) A sequência de endereços 000B 0000 < 0022 0000 < 0130 0000 precisa ser sempre crescente?

▶ Ver resolução

Resposta: Não, a ordem crescente não é obrigatória.

Por que aqui aparece crescendo: foi só a escolha de números do professor; nada na arquitetura força isso.

O que é obrigatório: cada bloco começar num endereço múltiplo de 4 KB (alinhamento).

O que garante a tradução certa: os ponteiros escritos nas tabelas (CR3 → ETP → página). A RAM pode guardar os blocos em qualquer ordem — quem manda é o caminho dos ponteiros, não o valor dos endereços.

Resumo de bolso (para decorar): dir = (linear >> 22) & 0x3FF; pg = (linear >> 12) & 0x3FF; offset = linear & 0xFFF. Depois: EETDIR = CR3 + dir×4 → lê ETP; EETPG = ETP + pg×4 → lê Epg; físico = Epg + offset. Mover a página em N quadros = somar/subtrair N × 0x1000 apenas ao Epg (e refazer a última soma). O resto da conta fica no lugar.

21. Trilha de Prova — Segmentação + Paginação no Modo Protegido

Esta é a seção que fecha o buraco do curso. Até aqui você estudou os dois assuntos separados: a segmentação (seções 5, 7, 10 e 10.1), que transforma Seletor:Offset em endereço linear; e a paginação (seções 19 e 20), que transforma endereço linear em endereço físico. O tema da sua prova é justamente as duas ligadas no mesmo exercício. É isso que fazemos aqui.

As duas metades nunca se contradizem — só se encaixam. A saída da primeira (endereço linear) é a entrada da segunda. Quem não enxerga a emenda trava na prova.

21.1 — O caminho completo do endereço (o mapa do tema)

Todo acesso à memória no modo protegido percorre este caminho. Guarde este desenho: ele é a espinha dorsal de qualquer questão do tema.

21.2 — O método integrado (roteiro único, do começo ao fim)

Use sempre este roteiro. A regra de ouro: faça uma etapa de cada vez. Você só passa para a paginação depois que a segmentação deu OK — se ela der GPF, nem existe endereço linear para paginar.

  1. Passo 1 — Identifique o registrador de deslocamento (offset).

    O enunciado diz a operação. Buscar instrução → EIP; ler/escrever dado → ESI/EDI; pilha → ESP/EBP.

  2. Passo 2 — Identifique o seletor e pegue o descritor.

    O registrador define o seletor: EIP→CS, ESP/EBP→SS, ESI/EDI→DS/ES/FS/GS. Na tabela de descritores, anote a Base e o Limite daquele seletor.

  3. Passo 3 — Calcule o endereço linear.

    Linear = Base do segmento + Offset

  4. Passo 4 — Teste de limite (a checagem de segurança).

    Se Linear > Limite → GPF, pare aqui (a paginação não roda). Senão, continue.

  5. Passo 5 — A paginação está desligada? Então acabou.

    Sem paginação: Físico = Linear. Ponto final.

  6. Passo 6 — (só com paginação ativa) Fatie o linear em 10 | 10 | 12.

    Saem três números: índice de diretório, índice de página e offset. Atalho: os 3 últimos dígitos hexa são o offset.

  7. Passo 7 — EETDIR = CR3 + índice_dir × 4.

    O conteúdo lido nesse endereço é a ETP (base da tabela de páginas).

  8. Passo 8 — EETPG = ETP + índice_pg × 4.

    O conteúdo lido ali é a Epg (início do quadro físico).

  9. Passo 9 — Físico = Epg + offset e confira.

    Os 3 últimos dígitos do físico têm de ser iguais aos do offset, e o byte tem de cair dentro do quadro Epg…Epg + 0xFFF.

Como decorar a diferença das duas metades: a segmentação usa soma (Base + Offset) e uma tabela de descritores; a paginação usa dois índices × 4 e três endereços (CR3 → ETP → Epg). A única coisa que as duas têm em comum é que a saída de uma é a entrada da outra: o endereço linear.

21.5 — Exemplo 3: quando o GPF barra antes da paginação

Nem toda questão chega até a paginação. Se a segmentação reprovar no teste de limite, o programa é abortado e a paginação nunca acontece.

Enunciado: O processador vai ler um dado do processo P1. ESI = 0000 0500. O segmento de dados do P1 é o seletor 0003 (Base 000a 0001, Limite 0000 0fff). Existe acesso à memória? Justifique.

Endereço Linear = 000a 0001 + 0000 0500 = 000a 0501 Teste: 000a 0501 > 0000 0fff → ❌ GPF! programa ABORTADO A paginação NEM RODA: o acesso foi barrado na segmentação.
Resposta: Não há acesso. O endereço linear 000a 0501 ultrapassa o limite 0000 0fff do segmento de dados → GPF. Como a falha acontece na etapa 1 (segmentação), o endereço físico nunca chega a ser calculado.
Moral de prova: sempre primeiro a segmentação (com o teste de limite). Só depois de um “OK” você parte para a paginação. Muitos alunos perdem pontos calculando o endereço físico de um acesso que deveria ter sido abortado.

▶ Ver resolução

Q3. Pegue a Q1 (P1, EIP = 0000 2000) e mova a página 3 quadros para trás. Qual o novo endereço físico?

▶ Ver resolução

3 quadros = 3 × 0x1000 = 0x3000. Para trás = subtrair do Epg:

0130 0000 − 0x3000 = 012F D000 (novo Epg).

O resto da conta (CR3, índices, eetdir, eetpg) não muda — só o conteúdo do EETPG e a última soma.

▶ Ver resolução

Sem paginação, físico = linear. A segmentação continua valendo, então:

Físico = 0000 3A00 ✓

Q4 (b). E na Q1, se a paginação estivesse ativa mas a página estivesse agora em 012F F000, qual o físico?

▶ Ver resolução

Mudou só a Epg (a caixa). Refaz-se apenas a última soma:

Q5. Processo P1, leitura de dados com ESI = 0000 0500 (seletor 0003). Existe acesso?

linear = 000a 0001 + 0000 0500 = 000a 0501.

Q6. (pegadinha conceitual) Por que o teste de limite tem de vir antes da paginação?

▶ Ver resolução

Porque o limite é a proteção do segmento: sem ele, um programa poderia “vazar” para além do seu espaço (ler dados de outro processo) — e a paginação, sozinha, traduziria alegremente qualquer linear.

O GPF barra o acesso antes de qualquer tradução. Por isso a ordem importa: 1º segmentar (e testar), 2º paginar.

Mover a página em N quadros = somar/subtrair N × 0x1000 só ao Epg.

23.3 — Como achar o ENDEREÇO LIMITE (a lógica do professor)

Guarde esta regra:

LIMITE de um segmento = BASE do PRÓXIMO segmento − 1

Traduzindo: o limite de um pedaço é o endereço logo antes de onde o próximo pedaço começa. Por que? Porque os pedaços são colados: o pedaço de trás termina no último endereço livre antes do da frente. É "um a menos" porque o endereço de início já pertence ao próximo segmento.

Vamos achar cada limite, na mão, um por um:

  1. Limite do Código (seletor 1000).

    O próximo segmento é a Pilha, que começa em 0057 af01. O código termina um endereço antes disso:

    0057 af01 − 1 = 0057 af00  ✓ (bate com a tabela)

  2. Limite da Pilha (seletor 100a).

    O próximo é Dados, que começa em 00c3 4100:

    00c3 4100 − 1 = 00c3 40ff  ✓

  3. Limite dos Dados (seletor 100b).

    O próximo é Extra, que começa em 00d6 7001:

    00d6 7001 − 1 = 00d6 7000  ✓

  4. Limite do Extra (seletor 100c).

    O Extra é o último segmento — não há "próximo". Então o limite dele é o topo da memória (o valor que o professor deu: 00e4 d193).

O que o limite faz na prática. Ao montar um endereço, o processador soma Base + Offset e depois compara o resultado (o endereço linear) com o limite do segmento. Se passou, o programa é morto na hora: é a falha de proteção geral (GPF — General Protection Fault). É a "trava de segurança" do modo protegido: impede que um programa invada o pedaço do outro.

Passo A — Onde está a instrução? (buscar a instrução)

A instrução é buscada usando o par CS:EIP. O CS é o seletor 1000, cuja base é 0010 0000. O EIP dado é 0000 2000. Somamos Base + EIP:

Linear da instrução = Base (CS) + EIP = 0010 0000 + 0000 2000 = 0010 2000

Teste do limite do código (0057 af00): 0010 2000 ≤ 0057 af00 → OK, a instrução pode ser buscada.

Passo B — Operando destino: 0006 5202 (segmento de Dados)

Operandos de dado usam, por padrão, o segmento de Dados (DS), aqui o seletor 100b, base 00c3 4100. O endereço linear é Base + Offset:

00c3 4100 ← base do segmento de Dados + 0006 5202 ← offset do operando destino ----------- 00c9 9302 ← endereço LINEAR do destino

Some coluna a coluna (hexa):

  • parte baixa: 4100 + 5202 = 9302  (0+2=2, 0+0=0, 1+2=3, 4+5=9);
  • parte alta: 00c3 + 0006 = 00c9  (c+0=c, 3+6=9);
  • não houve "vai um".

Conferindo em binário (basta olhar os mesmos bits): 1100 0011 0100 0001 0000 0000 + 0000 0110 0101 0010 0000 0010 = 1100 1001 1001 0011 0000 0010, que é justamente 00c9 9302.

Teste do limite dos Dados (00d6 7000): 00c9 9302 ≤ 00d6 7000 → OK. Este endereço linear (00c9 9302) é justamente o que alimenta a Questão 2.

A regra do ×4 (o jeito do professor, sem complicar):
  1. Escreva o índice em binário.
  2. Multiplique por 4 acrescentando 2 zeros à direita (4 = 100₂, então ×4 = andar 2 casas).
  3. Converta esse resultado para hexa (agrupe os bits de 4 em 4, da direita para a esquerda).
  4. Some com o valor que já está em hexa (CR3 ou ETP).
O offset (12 bits) é o único que não é multiplicado por 4 — por isso ele permanece em hexa como está (aqui, 302).

Passo 1 — Fatiar o endereço linear em 10 | 10 | 12 (em binário)

Um endereço linear tem 32 bits, lidos como índice da tabela de diretório (10 bits) + índice da tabela de páginas (10 bits) + OFFSET DA PÁGINA (12 bits). Primeiro, converta o linear para binário (cada dígito hexa vira 4 bits):

Passo 3 — Achar o EETP

Agora o índice da tabela de páginas: 0010 0110 01₂ (= 153). Multiplicando por 4 (acrescenta 2 zeros) e convertendo para hexa:

índice da tabela de páginas = 0010 0110 01₂ ( = 153 ) × 4 (acrescenta 00) = 0010 0110 0100₂ converte para hexa = 0010 0110 0100 → 264 → 0000 0264 EETP = ETP + (índice da tabela de páginas × 4) = 000f 0000 + 0000 0264 = 000f 0264

0. Como ler um diagrama de classes UML

Um diagrama de classes é só um desenho da estrutura do sistema. Pensa num organograma de empresa ou numa árvore genealógica: caixinhas com nomes e linhas ligando quem é quem. Aqui as caixinhas são classes e as linhas dizem como elas se relacionam.

Ordem de leitura (é sempre a mesma, não pule etapa):
1) leia o nome da caixa → 2) o que ela tem (atributos) → 3) o que ela faz (métodos) → 4) siga as setas que entram e saem dela.
É literalmente ler de cima para baixo e depois olhar as linhas. Nada de decorar tudo de uma vez: uma caixa por vez.

0.1 A caixa de uma classe (3 compartimentos)

┌──────────────────────────────┐ │ NomeDaClasse │ ← 1º: nome (em itálico se for ABSTRATA) ├──────────────────────────────┤ │ - atributoPrivado: Tipo │ ← 2º: atributos (o que ela TEM) │ # atributoProtegido: Tipo │ ├──────────────────────────────┤ │ + metodoPublico(): Tipo │ ← 3º: métodos (o que ela FAZ) │ # metodoAbstrato(): void │ (em itálico = abstrato) └──────────────────────────────┘
+ público (todo mundo pode usar) - privado (só a própria classe — nem as filhas) # protegido (a própria classe e as filhas)
Regra de ouro da visibilidade: a pergunta é sempre "quem pode mexer nesta informação?".
  • Atributos são "fechados" (- ou #) porque guardam os dados internos — a classe deve proteger o que está dentro dela. É a ideia de encapsulamento (a vitrine com tampa).
  • Métodos são "abertos" (+) porque são o serviço que a classe oferece para o mundo usar. Quem quer mexer nos dados de fora faz isso através dos métodos públicos.
A diferença entre - e # (essa é a dúvida clássica):
  • - privado: só a própria classe enxerga. Nem as filhas. Use quando o dado é assunto exclusivo daquela classe.
  • # protegido: a própria classe e as filhas enxergam. Use quando a filha precisa do dado para fazer o trabalho dela.
Exemplo (serpentário): na classe-mãe Serpente, peso é # (protegido) porque as filhas usam esse valor dentro dos métodos que elas reescrevem (ex.: a Sucuri, ao abater a presa, olha o próprio peso). Se fosse - (privado), só a classe Serpente veria o peso e as filhas ficariam "cegas" — não conseguiriam usar um dado que, afinal, herdaram.

E por que não deixar tudo + (público)? Porque aí qualquer código de fora poderia fazer serpente.peso = -999 e quebrar o sistema. "Fechar" os atributos impede isso; quem quiser mudar algo passa pelos métodos públicos, que controlam e validam o que pode.

1. Conceitos de POO

Cada conceito abaixo vem com o que é · como funciona · quando usar · onde usar. Leia como se fosse uma pergunta de prova.

Classe — o molde

O que é: a planta/descrição de um tipo. Diz quais atributos e métodos todo objeto daquele tipo terá.

Como funciona: você escreve a classe uma vez; a partir dela cria quantos objetos quiser.

Quando usar: sempre que houver um “tipo de coisa” no problema (Ônibus, Moto, Serpente).

Onde usar no diagrama: é o retângulo com 3 compartimentos.

Analogia 🍰: a classe é o molde do bolo. Sozinho ele não é doce, mas todo bolo feito dele sai com a mesma forma.

Objeto / Instância — o exemplar real

O que é: um caso concreto da classe, com valores próprios, existindo durante a execução.

Como funciona: Onibus a = new Onibus("ABC1D23", 80) cria um objeto.

Quando usar: quando precisar que algo “exista” em memória com seus dados.

Objeto × instância: é a mesma coisa; “instância” só olha para o objeto em relação à sua classe.

Analogia 🍰: são os bolos prontos. Usando o mesmo molde, cada bolo pode ter cobertura diferente (valores próprios).

Atributo — o estado (o que tem)

O que é: um dado guardado no objeto (ex.: placa, capacidade).

Tipos: de instância (cada objeto tem o seu) ou de classe / static (um só, compartilhado por todos).

Onde usar: 2º compartimento da caixa, geralmente com - ou #.

Analogia 🍰: é o sabor e a cobertura: cada bolo tem os seus, mesmo saindo do mesmo molde.

Método — o comportamento (o que faz)

O que é: uma ação do objeto. Assinatura = nome + parâmetros + tipo de retorno.

Concreto × abstrato: concreto tem corpo (diz como faz); abstrato só tem assinatura (cada filha escreve o corpo).

Onde usar: 3º compartimento, geralmente com +; abstrato em itálico.

Analogia 🍰: são as ações ("assar", "cortar", "servir"): o que o objeto sabe fazer.

Encapsulamento — proteger os dados

O que é: esconder o estado e só deixar mexer por métodos. Marca-se com a visibilidade (- privado, # protegido, + público).

Como funciona: atributos privados + getters para ler (sem setters, quando não deve mudar).

Quando usar: quando um dado não pode ser alterado livremente de fora.

Onde usar: é o uso do - e do # no diagrama.

Analogia 🔒: é a vitrine com tampa — você vê a torta, mas só pega por meio do atendente (os métodos).

Herança — “é um” (extends)

O que é: a filha recebe atributos e métodos da mãe e pode acrescentar ou sobrescrever.

Como funciona: teste da frase “X é um Y?”. Em Java, cada classe tem uma só superclasse.

Quando usar: só quando a subclasse é um caso da mãe (nunca só para reaproveitar código).

Onde usar no diagrama: linha cheia + triângulo vazio apontando para a mãe.

Analogia 🐶: "Cachorro é um Animal": já ganha de graça o que todo animal tem (nascer, comer) e só acrescenta o que é só dele (latir).

Contrato / Interface — “cumpre o contrato” (implements)

O que é: uma lista de métodos que a classe promete oferecer. Diz o quê, não como.

Como funciona: a classe pode assinar vários contratos ao mesmo tempo. Interface não guarda atributos (só métodos).

Quando usar: para uma capacidade que só algumas classes têm e que atravessa hierarquias diferentes (ex.: “ser elétrico”).

Onde usar no diagrama: caixa com «interface» + linha tracejada + triângulo vazio.

Analogia 🔌: é a tomada padrão (ou a CNH): o que importa é "encaixar no padrão". Qualquer aparelho/motorista que cumpra o combinado serve.

Classe abstrata — o molde incompleto

O que é: uma classe que não pode virar objeto; reúne o comum e pode ter métodos sem corpo.

Quando usar: quando não existe “um genérico” (não existe “veículo genérico”, “serpente genérica”) ou quando um método é comum a todas mas cada uma o faz de um jeito (vira abstrato).

Abstrata × interface: a abstrata pode ter atributos e código; a interface não.

Onde usar: «abstract» + nome em itálico.

Analogia 🍎: é a "fruta": todo mundo fala, mas ninguém compra "uma fruta" — compra maçã, banana. O mesmo vale para "veículo genérico".

Polimorfismo — uma chamada, vários comportamentos

O que é: o mesmo método, chamado do mesmo jeito, executa a versão do objeto real.

Como funciona: ligação dinâmica — decide na execução, não na compilação. Precisa de um tipo comum (mãe ou interface) + método sobrescrito.

Não confundir: mesmo nome com parâmetros diferentes = sobrecarga (decidida na compilação, não é polimorfismo).

Onde usar: num for sobre uma lista do tipo da mãe chamando o método; cada objeto responde do seu jeito.

Analogia 🎵: é o botão "tocar": no rádio sai música, na TV sai vídeo. Você aperta o mesmo botão; cada aparelho responde do seu jeito.

5. Diagrama: Cifra de Vigenère (Python & Java)

O que é, bem simples: uma cifra é um jeito de "embaralhar" um texto para ninguém entender, e depois conseguir voltar ao original. Imagine combinar com um amigo uma palavra secreta e, para cada letra da mensagem, "andar" no alfabeto o número de casas indicado pela letra da palavra secreta. Isso é a Cifra de Vigenère.

Por que este exemplo está no guia? Porque o código mostra duas ideias de POO: um contrato ("toda cifra sabe criptografar e descriptografar") e uma implementação (a Cifra de Vigenère, que faz isso de um jeito). E o mesmo programa aparece em Python e em Java, ótimo para comparar as duas linguagens.

5.1 A ideia e as fórmulas

Texto: A T T A C K A T D A W N Chave: L E M O N L E M O N L E (LEMON repete) Cifrado: L X F O P V E F R N H R Criptografar: C = (P + K) mod 26 Descriptografar: P = (C − K) mod 26 "mod 26" dá a volta no alfabeto: W(22)+L(11)=33 → 33 mod 26 = 7 → H
Regra do códigoO que faz
Caixa preservadaMaiúscula continua maiúscula; minúscula continua minúscula.
Não-letras passamEspaços, números e pontuação não mudam e não gastam letra da chave.
Sem acentos"Ação" vira "Acao" antes de cifrar.
Chave validadaSó A–Z contam; chave sem letras é recusada com erro.

Exemplo: "attack at dawn!" + LEMON → "lxfopv ef rnhr!"

5.3 O algoritmo em 3 passos (igual nas duas linguagens)

  1. Preparar a chave: remover acentos, deixar maiúscula, manter só A–Z e virar números. "Lémon 2!" → [11, 4, 12, 14, 13] (L,E,M,O,N). Chave sem letras → erro.
  2. Remover acentos: decompor (NFD) e apagar as marcas. Python: unicodedata (categoria "Mn"); Java: Normalizer.normalize(...,NFD) + regex \p{M}. "Ação" → "Acao".
  3. Processar (o laço): para cada caractere — (1) é maiúscula? minúscula? (senão mantém e segue); (2) pega o deslocamento da chave na posição posição % tamanhoDaChave; (3) novo = (ord(c) − base + sentido×desloc) mod 26; (4) posição++. sentido = +1 criptografa, −1 descriptografa.
"Ab!" com a chave "LE": c='A' base='A' chave L=11 (0+11)%26=11 → 'L' pos 0→1 c='b' base='a' chave E=4 (1+4)%26=5 → 'f' pos 1→2 c='!' não é letra → '!' pos 2 Resultado: "Lf!"

Eficiência: O(n) — percorre o texto uma vez; a chave é convertida uma vez no construtor.

7. Árvores e Percursos

O que é, bem simples: uma árvore é um jeito de organizar coisas em níveis — como as pastas do computador. Tem uma raiz (o topo), ela aponta para filhos, que apontam para outros, até chegar nas folhas (as pontas, que não têm filhos).

Por que importa: quando está organizada (menores à esquerda, maiores à direita), dá para achar quase tudo em poucos passos — a cada passo você descarta metade das opções, como procurar uma palavra no dicionário abrindo no meio, não página por página.

Percursos = as ordens possíveis de visitar tudo. O que muda entre elas é só quando a raiz é visitada. São três, mostradas abaixo.

7.1 Conceitos

  • Raiz: nó do topo, sem pai. Folha: nó sem filhos.
  • Árvore binária: no máximo 2 filhos (esquerda/direita).
  • Árvore binária de busca (BST): menores à esquerda, maiores à direita — busca descarta um lado a cada passo.

7.2 Os três percursos

Percorrer = visitar cada nó uma vez. Só muda quando a raiz é visitada (R = raiz, E = esquerda, D = direita; esquerda sempre antes da direita).

Em ordemE, R, DQuer valores ordenados (em BST)Listar do menor ao maior
Pós-ordemE, D, RFilhos antes do paiApagar árvore; somar pastas; calcular expressões

7.4 Aplicações

Árvore de expressão: pré-ordem = prefixa (× + 3 4 − 5 2), em ordem = infixa ((3+4)×(5−2)), pós-ordem = pós-fixa e calcula (3 4 + 5 2 − × → 21).

Pastas: pré-ordem lista; pós-ordem soma (o pai só sabe o tamanho depois dos filhos). Também: banco (árvore B), DOM, compiladores, árvore de decisão, organogramas.

A BST é ótima na memória, mas no disco cada nó visitado pode ser uma leitura de disco.

8. Big O e Eficiência

O que é, bem simples: Big O é só uma etiqueta que diz "quanto o trabalho cresce" quando a quantidade de dados aumenta. Não mede segundos — mede a forma da curva. Pensa em procurar um nome:

  • O(1) — "abrir a gaveta certa": sempre 1 passo, não importa se tem 10 ou 10 milhões. (hash)
  • O(log n) — "abrir o dicionário no meio": cada passo corta o resto pela metade. (busca binária, árvore)
  • O(n) — "ler a lista inteira": o trabalho cresce junto com os dados. (busca linear)
Saber isso é o que separa um programa que voa de um que trava.

8.1 Por que eficiência importa

  • Escala: 100 usuários ≠ 100 milhões — soluções ingênuas não escalam.
  • Custo real: tempo de processamento = espera do usuário, nuvem mais cara, bateria.
  • Previsibilidade: saber a complexidade prevê travamento antes de produção.
Big O é a linguagem para descrever e comparar o crescimento do esforço conforme n (tamanho da entrada) aumenta.

8.2 O que é Big O

  1. Ignora constantes: O(2n) e O(n) viram O(n) — importa a forma da curva.
  2. Foca no pior caso: limite garantido de esforço.
  3. Compara crescimento, não velocidade: não mede segundos.

10. Funções hash e colisões

O que é, bem simples: uma função hash é uma máquina de dar endereço. Você joga um nome ("Maria") e ela devolve um número (ex.: 7). Aí, para guardar ou achar "Maria", você não procura em tudo — vai direto na gaveta 7, como num armário de gavetas numeradas.

O detalhe que a aula resolve: às vezes duas chaves caem na mesma gaveta (isso é a colisão). A questão é: como escolher uma boa função e o que fazer quando isso acontece.

Recapitulando em uma frase: a chave vira um número, a divisão (resto) escolhe a gaveta, e para guardar ou buscar refaz-se a mesma conta — sem percorrer a tabela.

10.1 Uma boa função usa a ordem das letras

FunçãoContaProblema / ganho
Soma dos códigos"Roma" = 82+111+109+97 = 399Não vê a ordem → qualquer anagrama colide ("Amor" também dá 399). Só serve para ensinar.
Polinomial ×31h = h×31 + códigoA ordem conta: "Roma" e "Amor" caem em gavetas diferentes. Boa e barata.

O tamanho da tabela importa: mod 8 (potência de 2) olha só os últimos bits e amontoa; mod 11 (primo) espalha melhor. Na prática usam-se MurmurHash e xxHash.

10.2 Colisões são inevitáveis (e como tratar)

12 nomes em 11 gavetas → pelo menos uma colisão (princípio da casa dos pombos). Nenhuma função evita colisão; ela só espalha. A tabela precisa tratar:

Endereçamento abertoSem listas: se a gaveta está ocupada, vai para a próxima livre por uma regra fixa. A busca repete o mesmo caminho.
Fator de cargaitens ÷ gavetas. No HashMap o limite é 0,75: passou, a tabela dobra de tamanho e redistribui. As listas ficam com ~1 item e a busca segue O(1).

Lista que vira árvore: no Java, até 7 itens a gaveta é lista (busca O(n) naquela gaveta); a partir de 8 itens (tabela com 64+ gavetas) vira árvore balanceada (O(log n)). O hash escolhe a gaveta; a árvore organiza o que caiu nela.

10.4 Onde o hash aparece

  • Dicionários: dict (Python), HashMap (Java), Map (JS).
  • Bancos de dados: índices hash e hash join.
  • Distribuição: decidir em qual servidor cada registro fica (sharding).
  • Senhas: guarda-se o hash, nunca a senha.
  • Integridade: conferir se um download chegou intacto.
  • Git: cada commit é identificado pelo seu hash.

Propriedades de uma boa função: determinística (mesma entrada → mesma saída), rápida, espalha bem e tem tamanho fixo. As criptográficas (SHA-256) acrescentam: não dá pra voltar da saída à entrada, e é inviável achar duas entradas com o mesmo hash. Trocar uma letra (M→m) muda o resultado inteiro.

No MongoDB: o índice _id sempre existe e há o índice hashed (hash do valor como chave), usado para distribuir dados entre servidores.

Questão 3 — Por que "ser elétrico" vira interface e não subclasse?

Ver resposta comentada

Porque elétrico não é um tipo de veículo, é uma capacidade. BRT (um ônibus) e Metrô (que está fora dos ônibus) são coisas de ramificações diferentes, mas ambos são elétricos.

Se "elétrico" fosse uma superclasse (ex.: VeiculoEletrico), o BRT precisaria herdar de Onibus e de VeiculoEletrico ao mesmo tempo → herança múltipla, que o Java não permite. A interface resolve isso: ela "atravessa" as hierarquias sem esse problema, e ainda obriga a classe a fornecer os métodos do contrato.

Além disso, criar OnibusEletrico, MetroEletrico etc. multiplicaria classes a cada combinação nova. Com interface, basta um implements.

Questão 4 — O que é polimorfismo? Por que ele evita o if/instanceof?

Ver resposta comentada

Polimorfismo é: a mesma chamada (v.embarcar()) executa a versão do objeto real. Isso se chama ligação dinâmica — a decisão de "qual método rodar" acontece na execução, não na escrita do código.

Ele exige duas coisas: um tipo comum (a superclasse ou a interface) e um método sobrescrito nas filhas.

Sem polimorfismo você escreveria assim, feio e frágil:

if (v instanceof Onibus) { ... }
else if (v instanceof Metro) { ... }
else if (v instanceof BRT) { ... }

Toda vez que aparecesse um tipo novo, você teria de mexer nesse if (e rezar para não esquecer nenhum). Com polimorfismo basta:

for (Veiculo v : veiculos) v.embarcar();

O novo tipo "se vira sozinho" — nenhum código antigo muda. Por isso dizemos que o polimorfismo elimina os if de tipo.

  • Por que tração elétrica é interface: vale para BRT (que é um ônibus) e para Metrô (que não é) → cruza as duas ramificações sem herança múltipla.
  • Polimorfismo: for (VeiculoTransporteColetivo v : veiculos) v.embarcarPassageiro(); — o interestadual só embarca quem tem passagem, o urbano cobra na catraca, BRT e Metrô só registram (já pagaram na estação).

Questão 8 — Big O e hash (explique com suas palavras)

Ver resposta comentada

Busca linear O(n): se eu procuro um nome numa lista bagunçada, no pior caso olho todos os itens. Com 1 milhão de nomes, até 1 milhão de comparações — o trabalho cresce junto com os dados.

Busca binária O(log n): numa lista ordenada, olho o do meio e descarto metade, depois metade da metade… Com 1 milhão de itens, acho em cerca de 20 passos.

Hash O(1) em média: a função transforma a chave num número → gaveta. Vou direto na gaveta, sem percorrer nada. É praticamente 1 acesso, não importa se há 10 ou 10 milhões de itens (na média).

Importante: O(1) do hash é média. Se uma função hash for ruim e gerar muitas colisões, as gavetas viram listas compridas e a busca degenera para O(n).

Questão 9 — Colisão de hash: o que é e como tratar

Ver resposta comentada

Colisão é quando duas chaves diferentes caem na mesma gaveta (mesmo resultado da função). É inevitável — pelo princípio da casa dos pombos, se há mais chaves do que gavetas, alguma gaveta receberá duas.

Duas formas de tratar:

  • Encadeamento: cada gaveta guarda uma pequena lista. Para achar, percorro só a lista daquela gaveta (Maria? não. Pedro? sim).
  • Endereçamento aberto: não há listas; se a gaveta está ocupada, procuro a próxima livre por uma regra fixa, e a busca segue o mesmo caminho.

Fator de carga = itens ÷ gavetas. Quando passa de 0,75 (no HashMap), a tabela dobra de tamanho e redistribui, mantendo as listas curtas e a busca rápida.

Curiosidade: no Java, quando uma gaveta passa de 8 itens, a lista vira uma árvore balanceada e a busca naquela gaveta cai de O(n) para O(log n).

Questão 10 — Por que bancos de dados usam árvore B e não árvore binária?

Ver resposta comentada

Porque em disco cada nó visitado pode ser uma leitura de disco (operação lenta). Uma árvore binária de busca:

  • Tem muitos níveis: com 1 milhão de chaves, ≥ 20 níveis → até 20 leituras.
  • Pode ficar torta: se os dados entram em ordem, ela vira uma lista e a busca perde a graça.

A árvore B resolve os dois:

  • Várias chaves por nó (centenas) → poucos níveis. Com 500 chaves/nó, 3 níveis guardam ~125 milhões de chaves.
  • É sempre balanceada: quando um nó enche, ele se divide, e todas as folhas ficam na mesma profundidade.

Na prática: o MySQL (InnoDB) guarda a tabela numa árvore B+; o MongoDB (WiredTiger) guarda coleção e índices em árvore B. A ideia da BST continua (comparar e descer), só que "mais chaves por nó = menos idas ao disco".
