1. Fundamentos do Computador

Antes de entender como a arquitetura Intel funciona, precisamos saber como um computador se comunica internamente. Existem 3 blocos fundamentais:

┌──────────────────────────────────────────────────────────────┐ │ BARRAMENTO (BUS) │ │ ┌───────────────┐ ┌───────────────┐ ┌───────────────┐ │ │ │ Endereço │ │ Dados │ │ Controle │ │ │ └───────────────┘ └───────────────┘ └───────────────┘ │ │ ▼ ▼ ▼ │ │ ┌───────────────┐ ┌───────────────┐ ┌───────────────┐ │ │ │ CPU │ │ MEMÓRIA │ │ E/S │ │ │ │ (UC / ULA) │ │ │ │ (In / Out) │ │ │ └───────────────┘ └───────────────┘ └───────────────┘ │ └──────────────────────────────────────────────────────────────┘

1.1 Barramento (Bus)

O que é: É o "caminho" por onde viajam as informações entre os componentes do computador. Pense nele como uma autovia com 3 faixas:

FaixaO que transportaPor que existe
EndereçoIndica ONDE na memória o dado está ou deve ser gravadoSem ela, o processador não saberia onde ler/escrever
DadosOs valores reais (números, instruções, etc.)É a "carga" que está sendo transportada
ControleSinais de comando (ler, escrever, clock)Coordena quem fala, quem ouve e quando

1.2 CPU (Unidade Central de Processamento)

O "cérebro" do computador. Suas principais partes:

ComponenteFunção
UC (Unidade de Controle)Busca, decodifica e coordena a execução das instruções. É o "maestro".
ULA (Unidade Lógica e Aritmética)Realiza cálculos (soma, subtração, AND, OR, etc.).
PPUProcessamento auxiliar (frequentemente associado a operações de ponto flutuante).
MMU (Memory Management Unit)Gerencia a tradução de endereços lógicos → físicos (segmentação e paginação).
RegistradoresMemórias ultrarrápidas internas da CPU. Guardam dados, endereços e estado da execução.
A CPU também se comunica pelo barramento: envia endereço e controle e recebe/envia dados.

1.3 Memória

TipoTecnologiaCaracterísticasPor que importa
Principal (RAM)DRAM (Dynamic RAM)Grande capacidade, mais barata, precisa de refresh constanteArmazena programas e dados em execução
CacheSRAM (Static RAM)Pequena capacidade, muito rápida, não precisa de refreshReduz a espera da CPU por dados da RAM

Níveis de Cache:

  • L1 — Dentro do core, mais rápida (cerca de 1-4 ns), menor capacidade (~32-64 KB)
  • L2 — Pode ser dentro ou fora do core, intermediária (~10 ns, 256 KB-1 MB)
  • L3 — Compartilhada entre cores, maior (~30 ns, 2-64 MB)
Quanto mais perto da CPU, mais rápida e mais cara é a memória. A cache "aproxima" os dados frequentes da CPU para não ficar esperando a RAM lenta.

1.4 Entrada/Saída (I/O)

São os dispositivos que permitem ao computador receber dados (input) e enviar dados (output) — teclado, mouse, monitor, disco rígido, rede, etc.

2. Arquitetura Intel x64

2.1 Conceitos Fundamentais

Tamanho da palavra: É a capacidade mínima de bits para representar a instrução mais simples do processador. Ela também define a quantidade mínima de bits que a unidade decodificadora processa a cada ciclo de decodificação.

Por que isso importa? Se o processador decodifica de 8 em 8 bits, então a palavra mínima é de 8 bits. Uma instrução como ADD END1, END2 é quebrada em pedaços de 8 bits para ser interpretada. Uma palavra maior permite instruções mais complexas e endereçamento maior, mas exige circuitos mais sofisticados.
Instrução: ADD END1, END2 → END1 ← END1 + END2 ┌─────────────┐ ┌─────────────┐ │ Opcode │ │ Operandos │ │ (operador) │ │ (endereços) │ └──────┬──────┘ └──────┬──────┘ │ │ ▼ ▼ Decodifica Decodifica de 8 em 8 de 8 em 8 Se a palavra = 8 bits, cada ciclo lê/decodifica 8 bits
Relação: + tamanho da palavra = + núcleos simultâneos de decodificação
Uma palavra maior permite que a CPU decodifique mais instruções ao mesmo tempo, aumentando o paralelismo interno.

Compatibilidade Binária

Dois processadores possuem compatibilidade binária se:

  • Possuem o mesmo conjunto de instruções (ISA — Instruction Set Architecture)
  • Possuem a mesma representação em bits para essas instruções
OBS: TODAS as instruções devem ser iguais. Se apenas uma for diferente, toda a compatibilidade binária se perde. Um programa compilado para um não roda no outro.

Capacidade de Endereçamento

É a capacidade máxima de endereços que um processador consegue gerar em um sistema de memória.

  • Na maioria dos sistemas, cada endereço armazena 1 byte (8 bits) de informação.
  • Se o processador usa N bits para formar um endereço, ele consegue endereçar 2N bytes.
Bits de endereçoEspaço endereçávelExemplo de uso
16 bits2¹⁶ = 64 KB8086
20 bits2²⁰ = 1 MB80286 (modo real)
32 bits2³² = 4 GB80386+
64 bits2⁶⁴ = 16 EBArquitetura x64 moderna

Clock (Frequência do Processador)

O clock é o "batimento cardíaco" do processador. É um sinal elétrico que pulsa em uma frequência fixa, e a cada pulso (ciclo) o processador executa uma operação básica.

ConceitoO que éExemplo
Frequência de clockQuantos milhões/bilhões de ciclos por segundo (MHz/GHz)3.5 GHz = 3.500.000.000 ciclos/segundo
Ciclo de clockTempo entre dois pulsos consecutivosEm 3.5 GHz: ~0.28 nanosegundos por ciclo
CPI (Cycles Per Instruction)Quantos ciclos uma instrução leva para executarUma instrução simples pode levar 1 ciclo; complexa, vários
Velocidade ≠ Clock sozinho. Dois processadores com o mesmo clock podem ter velocidades diferentes por causa da arquitetura interna (pipeline, cache, número de núcleos). Mas, tudo o mais constante, maior clock = mais operações por segundo.
Relação com o tamanho da palavra: Um processador com palavra de 64 bits processa mais dados por ciclo que um de 32 bits, mesmo no mesmo clock. A velocidade real depende de: Velocidade = Clock × Bits da palavra / CPI

Registradores especiais de 64 bits:

Modo de Compatibilidade (32 bits dentro de 64 bits):

  • São utilizados apenas os 8 primeiros registradores de propósito geral (RAX-RSP) na sua versão de 32 bits (EAX, EBX...)
  • O RIP também opera como EIP (32 bits)
  • O RFLAGS opera como EFLAGS (32 bits)
  • Os seletores de segmento continuam com 16 bits sempre
  • Programas compilados para 32 bits rodam normalmente nesse modo

Velocidade vs Software

Uma distinção importante feita pelo professor:

AspectoDomínioO que define
VelocidadeHardware / CircuitoPhysicamente quão rápido o processador opera (clock, pipeline, cache)
Praticidade e modificaçãoPrograma / SoftwareComo o código é escrito, otimizado e facilmente alterável
Hardware define o limite máximo de velocidade. Software define o quão eficientemente esse limite é aproveitado.

3. Modo Protegido

O modo protegido é o modo de operação principal dos processadores Intel modernos (a partir do 80286, consolidado no 80386). Nele, o sistema operacional controla o acesso à memória e protege processos uns dos outros.

Quando processadores de 64 bits operam no modo protegido (compatibilidade x86), eles têm estas características:

  • Endereços de 32 bits → espaço de endereçamento de 2³² = 4 GB
  • Registradores operam com 32 bits
  • Os registradores estão distribuídos em 3 grupos

Os 3 grupos de registradores no modo protegido:

  1. Registradores Gerais (EAX, EBX, ECX, EDX, etc.)
  2. Registradores de Deslocamento/Offset (EIP, ESP, EBP, ESI, EDI)
  3. Registrador de Flags (EFLAG)

Além disso, os seletores de segmento operam com 16 bits.

Formas de gerenciar o espaço de endereçamento:

MétodoComo funcionaQuando usado
SegmentaçãoA memória é dividida em blocos (segmentos) de tamanhos variadosSempre ativo no modo protegido
PaginaçãoA memória é dividida em páginas de tamanho fixo (tipicamente 4 KB)Opcional, gerenciado pelo SO
Segmentação + PaginaçãoPrimeiro segmenta, depois paginaCombinação dos dois métodos

4.3 Registrador EFLAG

Cada bit desse registrador sinaliza algo sobre a última instrução executada. Os bits mais importantes:

BitSiglaSignificado
0CFCarry Flag — houve transporte (overflow) em unsigned
2PFParity Flag — número de bits 1 no byte baixo é par
6ZFZero Flag — resultado da operação foi zero
7SFSign Flag — resultado é negativo (bit de sinal = 1)
11OFOverflow Flag — houve overflow em signed
Os flags são usados em instruções de salto condicional (JE, JNE, JG, JL...). Exemplo: após um CMP, se os valores forem iguais, o ZF fica em 1, e o JE (Jump if Equal) usa esse flag para decidir se pula.

5. Endereçamento de Memória no Modo Protegido

Existem 3 tipos de endereçamento:

  1. Endereço Lógico (Virtual) = par (Seletor : Offset)
  2. Endereço Linear = Endereço base do segmento + Offset
  3. Endereço Físico = o endereço real na RAM
┌────────────────────────┐ │ Endereço Lógico │ Seletor : Offset │ (CS:EIP, SS:ESP) │ └────────────┬───────────┘ │ ← Unidade de Segmentação (soma base + offset) ▼ ┌────────────────────────┐ │ Endereço Linear │ Base do segmento + Offset └────────────┬───────────┘ │ ┌──────┴───────┐ │ Paginação? │ ├─ Não ────────┤──→ Físico = Linear └─ Sim ────────┘──→ Físico = via tabela de páginas │ ▼ ┌────────────────────────┐ │ Endereço Físico │ → vai para a RAM └────────────────────────┘

5.1 Pares de Endereçamento (Seletor : Offset)

SeletorRegistrador OffsetSegmentoO que indica
CSEIPCódigoEndereço da próxima instrução a ser executada
SSESPPilhaTopo da pilha
SSEBPPilhaBase da pilha (acesso sem desempilhar)
DSESI / EDIDadosSeletor de dados — pode trabalhar com ambos
ESESI / EDIDados extraSeletor de dados extra — pode trabalhar com ambos
FSESI / EDIDados extraSeletor de dados extra — pode trabalhar com ambos

Por que esses pares? A arquitetura Intel separa endereços por FINALIDADE. Código, dados e pilha ficam em segmentos diferentes para que um programa não consiga sobrescrever seu próprio código acidentalmente (proteção).

Importante: Qualquer seletor de dados (DS, ES, FS, GS) pode ser pareado com tanto ESI quanto EDI. A escolha depende de qual seletor o SO alocou para o segmento que está sendo acessado.

5.2 Como Identificar Qual Usar (Guia Prático)

Regra de ouro: O enunciado da questão te diz QUAL operação está sendo feita. A operação define o registrador. O registrador define o seletor.

A tabela abaixo é a sua "chave de resolução". Sempre que aparecer uma questão prática, refaça essa pergunta:

O enunciado diz...OperaçãoRegistradorSeletorPor quê?

"busca de instrução"
"executar instrução"
"o processador vai buscar"		 Código EIP CS EIP sempre aponta para a próxima instrução a executar
"ler dado"
"buscar dado da memória"
"operando de leitura"
"trazer dado para o processador"		 Leitura ESI DS (ou ES/FS/GS) ESI = Source Index = índice de ORIGEM. O seletor depende de qual segmento o SO alocou
"escrever dado"
"gravar resultado"
"armazenar em memória"
"operando de escrita"		 Escrita EDI ES (ou DS/FS/GS) EDI = Destination Index = índice de DESTINO. O seletor depende de qual segmento o SO alocou
"PUSH"
"empilhar"
"topo da pilha"
"desempilhar" (no topo)		 Pilha (topo) ESP SS ESP = Stack Pointer = aponta para o TOPO da pilha

"base da pilha"

"acesso à pilha sem desempilhar"		 Pilha (base) EBP SS EBP = Base Pointer = ponto fixo para acessar dados na pilha

Como Decidir na Prática (Fluxograma Mental)

┌──────────────────────────────────────────────────────────┐ │ O ENUNCADO MENCIONA... │ │ │ │ "próxima instrução" / "buscar instrução" │ │ → EIP + CS │ │ │ │ "ler dado" / "buscar dado" / "operando de leitura" │ │ → ESI + DS (ou ES/FS/GS, depende do enunciado) │ │ │ │ "escrever" / "gravar" / "armazenar resultado" │ │ → EDI + ES (ou DS/FS/GS, depende do enunciado) │ │ │ │ "PUSH" / "empilhar" / "topo da pilha" │ │ → ESP + SS │ │ │ │ "POP" / "desempilhar" │ │ → ESP + SS (primeiro incrementa, depois le) │ │ │ │ "acesso à pilha" / "EBP" / "frame" │ │ → EBP + SS │ │ │ │ NÃO MENCIONA NADA ESPECÍFICO? │ │ → Pergunte: qual registrador de deslocamento aparece? │ │ Use a tabela de pares para descobrir o seletor │ │ (DS/ES/FS/GS funcionam com ESI e EDI) │ └──────────────────────────────────────────────────────────┘
Atalho mental para não errar:
  • EIP = Instruction Pointer → Código → CS
  • ESI = Source Index → Saída (origem) → Leitura → DS (ou ES/FS/GS)
  • EDI = Destination Index → Destino → Escrita → ES (ou DS/FS/GS)
  • ESP = Stack Pointer → Pilha (topo) → SS
  • EBP = Base Pointer → Pilha (base) → SS

Lembre-se: DS, ES, FS e GS são intercambiáveis — qualquer um deles pode trabalhar com ESI ou EDI. O enunciado da questão sempre diz qual seletor usar.

5.3 Exemplo Rápido de Identificação

Pergunta: "Dado um PUSH EAX, onde ESP = 0x00C00FF0, identifique os 5 passos."

Passo 1: O enunciado diz "PUSH" → operação de pilha → registrador = ESP

Passo 2: ESP trabalha com SS → vá à tabela de descritores e ache qual seletor é o de pilha

A partir daqui é só aplicar a fórmula: Linear = Base + ESP

Se o enunciado não diz explicitamente qual operação é, procure o nome do registrador que aparece no enunciado. Ex: se aparece ESI = 0x12345, automaticamente é leitura de dados. O seletor pode ser DS, ES, FS ou GS — o enunciado sempre diz qual.

6. Segmentos de Memória

Quando um programa é executado no modo protegido, o SO aloca segmentos na memória para ele:

TipoQuantidade por programaFunçãoTamanho
Código (CS) 1 apenas Armazena as instruções do programa 1 byte a 4 GB
Pilha (SS) 1 apenas Cálculos intermediários e troca de contexto 1 byte a 4 GB
Dados (DS, ES, FS, GS) Até 4 Armazena as variáveis do programa 1 byte a 4 GB cada
Por que separar? A separação permite que o SO aplique permissões diferentes a cada segmento. Por exemplo: o segmento de código pode ser "somente leitura" (não pode ser modificado), evitando que o programa corrompa suas próprias instruções.

7. Tabela de Descritores de Segmento

É a tabela que o SO usa para definir cada segmento na memória. Cada entrada (descritor) contém 4 campos:

CampoDescriçãoPor que importa
SeletorNúmero único de 8 bits que identifica o segmento na tabelaÉ como um "ID" — não pode se repetir
Endereço BasePrimeiro endereço do segmento na memóriaUsado no cálculo: Linear = Base + Offset
Endereço LimiteÚltimo endereço permitido do segmentoUsado para verificação de segurança
Direito de AcessoDefine a camada do SO à qual o segmento pertenceControla quem pode acessar (ver item abaixo)

TESTE DE SEGURANÇA: Toda vez que o endereço linear é calculado, ele é comparado com o endereço limite. Se endereço linear > endereço limite, ocorre GPF (General Protection Fault) — falha de proteção geral. O programa é abortado imediatamente.

Como identificar qual segmento é qual? Analise os endereços base. Sequentes = mesmo processo. A ordem típica na memória (de endereço baixo para alto) é: Código → Pilha → Dados → Extra. O primeiro seletor (0001 para P1, 0140 para P2) é sempre o de código.

Camadas do Sistema Operacional (Direito de Acesso)

O SO é implementado em camadas (rings), de 0 a 3:

RingCamadaPrioridadeExemplo
Ring 0KernelMÁXIMANúcleo do SO, drivers
Ring 1Serviços do SOAltaServiços intermediários
Ring 2Serviços do SOMédiaBibliotecas do sistema
Ring 3Aplicativos (APPS)MÍNIMAProgramas de usuário
Um segmento com direito de acesso "Ring 3" não pode acessar um segmento com "Ring 0". Isso protege o kernel de programas com bugs ou maliciosos.

Tamanho da Tabela de Descritores e Multitarefa:

  • Cada tabela de descritores de segmento tem 8 KBytes de tamanho
  • Existem várias tabelas de descritores na memória, definidas pelo SO
  • Isso permite que vários segmentos estejam definidos simultaneamente
  • Essa estrutura viabiliza a criação de sistemas operacionais multitarefa na arquitetura PC
  • Porém, apenas um processo por vez está sendo executado pelo processador (rodízio)
Na prova: Se perguntarem "por que a arquitetura Intel suporta multitarefa?", a resposta é: porque existem várias tabelas de descritores de 8KB cada, permitindo que múltiplos segmentos de múltiplos processos estejam definidos na memória ao mesmo tempo, com o SO rodiziando entre eles.

8. Processos e Escalonamento

Processo: É um programa que está em execução. Vários processos podem estar definidos na memória, mas apenas um por vez está sendo executado pelo processador.

Escalonamento: O SO decide qual processo usa o processador e por quanto tempo (rodízio / time-sharing).

Contexto de Hardware: É o conjunto de informações dos registradores internos do processador para um dado processo. Quando o processo é trocado:

  • O contexto do processo antigo é salvo no segmento TSS (Task State Segment) na memória principal
  • O contexto do novo processo é restaurado do TSS dele

Fórmula: Contexto do Processo = Contexto de Software + Contexto de Hardware

Quando o processo retoma, ele continua exatamente de onde parou.

9. Detalhamento dos Seletores e Registradores

9.1 CS : EIP (Código)

CS (Code Segment) — seletor de código. Identifica o segmento onde está o código do programa em execução.

EIP (Instruction Pointer) — armazena o endereço da próxima instrução a ser executada.

  • A cada instrução executada, o EIP é atualizado automaticamente (incrementado de 4 em 4 bytes na arquitetura 32 bits)
  • O EIP é um ponteiro: é inicializado pelo programa e alterado por saltos (JMP, CALL, RET)

9.2 SS : ESP (Pilha — Topo)

Registrador ESP (Extended Stack Pointer) — ponteiro de pilha.

  • Armazena o endereço lógico do topo da pilha
  • Na arquitetura Intel, a pilha cresce de cabeça para baixo (endereços decrescentes)
  • Empilhar (PUSH): o dado é colocado no endereço apontado por ESP, depois o ESP é pós-decrementado em 4 bytes
  • Desempilhar (POP): o ESP é pré-incrementado em 4 bytes, depois o dado é lido da nova posição
PILHA NA ARQUITETURA INTEL (cresce para BAIXO) Endereço alto (início da pilha) ┌─────────────┐ 0x00C01000 │ Dado 1 │ ├─────────────┤ 0x00C00FFC ← ESP apontava aqui antes do PUSH │ Dado 2 │ ├─────────────┤ 0x00C00FF8 │ Dado 3 │ ├─────────────┤ 0x00C00FF4 │ (vazio) │ ← ESP aponta para VAZIO (topo) └─────────────┘ 0x00C00FF0 Endereço baixo PUSH 5: 1. Coloca 5 no endereço 0x00C00FF0 2. ESP = ESP - 4 → agora ESP = 0x00C00FEC POP: 1. ESP = ESP + 4 → agora ESP = 0x00C00FF0 2. Lê o dado de 0x00C00FF0
Por que a pilha cresce para baixo? É uma convenção da arquitetura Intel. Isso significa que empilhar DECREMENTA o ESP e desempilhar INCREMENTA o ESP. Não confunda!

9.3 SS : EBP (Pilha — Base)

EBP (Extended Base Pointer) — ponteiro base de pilha.

É um ponteiro auxiliar que permite acessar dados dentro da pilha sem precisar desempilhar. É como uma "janela" fixa para olhar dentro da pilha.

Muito usado em frames de função: quando uma função começa, EBP salva o topo antigo da pilha e ESP desce para alocar espaço local. Assim, os parâmetros e variáveis locais ficam acessíveis via EBP com offset fixo.

9.4 DS/ES/FS/GS : ESI/EDI (Dados)

SeletorNomeFunção
DSData SegmentSeletor principal de dados
ESExtra SegmentSegmento de dados extra
FS, GSExtra segmentsSegmentos de dados adicionais (usados pelo SO para TLS, etc.)

ESI (Source Index) — armazena o endereço de leitura de dados.

EDI (Destination Index) — armazena o endereço de escrita de dados.

Juntos, ESI e EDI são usados em instruções como MOVS (movimentar dados de um endereço para outro), onde ESI aponta para a origem e EDI para o destino.

10. Os 5 Passos da Execução de uma Instrução

QUANDO UM PROCESSADOR VAI EXECUTAR UMA INSTRUÇÃO, ESTES SÃO OS 5 PASSOS:

  1. Identificar os registradores de deslocamento
    De acordo com a instrução, identifica quais registradores de deslocamento (offset) ela utilizará. Ex: se é uma instrução de código, usará EIP; se acessa dados, usará ESI ou EDI.
  2. Identificar os seletores de segmento
    Identifica quais seletores de segmento estão associados aos registradores de deslocamento. Ex: se o offset é EIP, o seletor é CS; se é ESI, o seletor é DS.
  3. Calcular o endereço linear
    Localiza na tabela de descritores de segmento o endereço base correspondente ao seletor, e soma com o offset:
    Endereço Linear = Endereço Base do Segmento + Offset
  4. Teste de segurança (Limite)
    Compara o endereço linear com o endereço limite. Se linear > limite → GPF e o programa é abortado.
  5. Definir o endereço físico
    Se a paginação estiver desativada: endereço físico = endereço linear.
    Se a paginação estiver ativa: o endereço linear é traduzido usando tabelas de páginas para obter o endereço físico.
Resumo visual: Seletor:Offset → Linear = Base + Offset → Teste do Limite → Físico → RAM

Como identificar qual segmento é qual (P1): Analise a ordem dos endereços base: 00001a00 → 0004defe → 000a0001 → 000d1000. Na memória, a ordem é Código → Pilha → Dados → Extra. Então: 0001=Código, 0002=Pilha, 0003=Dados, 0004=Extra. Para P2 segue a mesma lógica.

Enunciado: O processador está executando o processo P1. O registrador EIP = 0000 3000. Execute os 5 passos.

Resolução passo a passo:

▸ Passo 1 — Identificar o registrador de deslocamento

A instrução está no segmento de código. O registrador de deslocamento é EIP (Instruction Pointer).

▸ Passo 2 — Identificar o seletor de segmento

EIP trabalha com CS. No P1, o seletor de código é 0001. Pela tabela: Base = 0000 1a00, Limite = 0004 DFFD.

Fórmula: Endereço Linear = Endereço Base + Offset Endereço Linear = 0000 1a00 + 0000 3000 Endereço Linear = 0000 4a00

Sem paginação: Endereço Físico = 0000 4a00

Exemplo 2: Lendo Dados do P1 (DS : ESI)

Enunciado: O processador vai ler um dado do processo P1. O registrador ESI = 0000 0500. Execute os 5 passos.

Resolução passo a passo:

▸ Passo 1 — Registrador de deslocamento: ESI (leitura de dados).

▸ Passo 2 — Seletor: DS. No P1, o segmento de dados é seletor 0003. Base = 000a 0001, Limite = 0000 0fff.

▸ Passo 3

Endereço Linear = 000a 0001 + 0000 0500 Endereço Linear = 000a 0501

▸ Passo 4

Linear: 000a 0501 Limite: 0000 0fff 000a 0501 > 0000 0fff → ❌ GPF! Abortado!

⛔ O endereço linear excede o limite do segmento de dados. O programa é abortado.

Por quê? O offset 0500 é maior que o limite 0fff do segmento de dados do P1. O processador bloqueia o acesso.

Exemplo 3: Escrevendo Dados no P2 (ES : EDI)

Enunciado: O processador vai escrever no segmento extra do processo P2. EDI = 0000 1000. Execute os 5 passos.

Resolução passo a passo:

▸ Passo 1 — Registrador de deslocamento: EDI (escrita de dados).

▸ Passo 2 — Seletor: ES. No P2, o segmento extra é seletor 037b. Base = 0070 000f, Limite = 0078 00ff.

▸ Passo 3

Endereço Linear = 0070 000f + 0000 1000 Endereço Linear = 0071 000f

▸ Passo 4

Linear: 0071 000f Limite: 0078 00ff 0071 000f ≤ 0078 00ff → ✅ OK!

▸ Passo 5 — Endereço físico = 0071 000f (sem paginação).

Exemplo 4: Empilhando no P1 (SS : ESP — PUSH)

Enunciado: Vamos executar PUSH EAX no processo P1, com EAX = 42 e ESP = 0006 0000. Execute os 5 passos.

Resolução passo a passo:

▸ Passo 1 — PUSH acessa a pilha → registrador = ESP.

▸ Passo 2 — Seletor: SS. No P1, a pilha é seletor 0002. Base = 0004 defe, Limite = 000a 0000.

▸ Passo 3

Endereço Linear = 0004 defe + 0006 0000 Endereço Linear = 000a de fe (soma hex: 4+6=A, de+00=de, fe+00=fe)

▸ Passo 4

Linear: 000a defe Limite: 000a 0000 000a defe > 000a 0000 → ❌ GPF! Abortado!

⛔ O ESP aponta para um endereço acima do limite da pilha.

O que aconteceu? O valor de ESP (0006 0000) somado à base (0004 defe) resultou em um endereço linear que ultrapassa o limite da pilha (000a 0000). Isso pode indicar overflow de pilha.

O que acontece DEPOIS do cálculo (a instrução em si):

1. Escreve o valor 42 no endereço 000a defe 2. ESP = ESP - 4 = 0005 fffe (pós-decremento) Estado da pilha: ┌─────────────┐ 000a de fe + 4 │ (antigo) │ ├─────────────┤ 000a de fe ← estava aqui, agora gravou 42 │ 42 │ ├─────────────┤ 0005 fffe ← ESP agora aponta aqui (vazio) └─────────────┘

Endereços Explícitos vs Implícitos no PUSH/POP

Uma-instrução PUSH ou POP manipula DOIS endereços lógicos simultaneamente:

TipoO que éEm PUSHEm POP
Explícito O endereço que aparece escrito na instrução O endereço SRC (origem dos dados) — pertence ao segmento de dados O endereço DST (destino) — pertence ao segmento de dados
Implícito O endereço que está escondido no registrador ESP — não aparece na instrução O topo da pilha (SS:ESP) — onde o dado será gravado O topo da pilha (SS:ESP) — de onde o dado será lido

Na prova: Se perguntarem "quais endereços lógicos uma instrução PUSH manipula?", a resposta é: o endereço explícito (SRC no segmento de dados) e o endereço implícito (SS:ESP no topo da pilha). O mesmo vale para POP, mas com DST como explícito.

Enunciado: O processador vai acessar um dado usando o segmento de código do P2 (seletor 0140) com ESI = 0020 0000. O que acontece?

▸ Passo 2 — Seletor: 0140 (Código do P2)

Observação: Passo 4 em Operações com Dois Endereços

Quando uma instrução como MOV [EDI], [ESI] envolve dois endereços (SRC e DST), o Passo 4 funciona assim:

┌────────────────────────────────────────────────────────────┐ │ OPERAÇÃO COM DOIS ENDEREÇOS (ex: MOV DST, SRC) │ │ │ │ PASSO 3: calcular AMBOS os endereços lineares │ │ Linear SRC = BaseSRC + OffsetSRC │ │ Linear DST = BaseDST + OffsetDST │ │ │ │ PASSO 4: cada endereço é comparado com o SEU próprio │ │ limite (da tabela de descritores): │ │ Linear SRC ≤ LimiteSRC? → se não, GPF! │ │ Linear DST ≤ LimiteDST? → se não, GPF! │ │ │ │ ⚠️ NÃO se compara Linear SRC com Linear DST! │ │ ⚠️ Cada endereço é testado contra o limite do SEU │ │ segmento de origem/destino. │ └────────────────────────────────────────────────────────────┘

Exemplo: Se o professor fizer MOV [EDI], [ESI] no P1:

  • ESI = 0000 0500 → Linear SRC = 000a 0501 (segmento 0003, limite 0000 0fff) → ❌ GPF!
  • EDI = 0000 0100 → Linear DST = 000d 1100 (segmento 0004, limite 000c 7800) → ❌ GPF!

Como o SRC já deu GPF, a instrução é abortada antes mesmo de calcular o DST.

12. Glossário de Termos

GPF (General Protection Fault)
Falha de proteção geral. Ocorre quando o processador detecta uma violação de memória (endereço fora do limite, acesso não autorizado, etc.) e aborta o programa.
TSS (Task State Segment)
Segmento na memória onde o contexto de hardware de um processo é salvo quando ele é trocado pelo escalonador.
Contexto de Hardware
Conjunto de valores dos registradores internos do processador para um processo específico.
Contexto do Processo
= Contexto de Software + Contexto de Hardware. Representa todo o estado de um processo.
Escalonamento
Serviço do SO que decide qual processo executa e por quanto tempo (round-robin, prioridades, etc.).
Processo
Programa que está em execução. Quando definido na memória mas não está rodando, é chamado de "programa".
Endereço Lógico / Virtual
Par (Seletor : Offset) que representa o endereço "visto" pelo programa. Traduzido pelo hardware para endereço físico.
Segmentação
Técnica de dividir a memória em blocos de tamanho variável (segmentos), cada um com permissões próprias.
Paginação
Técnica de dividir a memória em páginas de tamanho fixo (tipicamente 4 KB) para gerenciamento eficiente.
Ring (Anel)
Nível de privilégio no modo protegido. Ring 0 = kernel (máxima privilégio), Ring 3 = aplicativos (mínima).
Clock
Frequência do processador em Hz/MHz/GHz. Cada ciclo permite uma operação básica. Maior clock = mais operações/segundo (tudo o mais constante).
CPI (Cycles Per Instruction)
Número médio de ciclos de clock que uma instrução leva para executar.
ISA (Instruction Set Architecture)
Conjunto de instruções que um processador consegue executar. Define a compatibilidade binária entre processadores.
Modo de Compatibilidade
Submodo de 64 bits que roda programas de 32 bits. Usa apenas os 8 primeiros registradores (versão de 32 bits).
Explicit vs Implícito
Em PUSH/POP, o endereço "explícito" aparece na instrução (segmento de dados). O "implícito" está escondido no registrador ESP (segmento de pilha).
